# 逐页前端性能：会话、模型与连接器

本轮在 `b1c758d` 的前端优化基础上，修改三页的生产路径：会话工作流列表的按需构建、模型目录的端点索引与分区复用、连接器目录的过滤与归属统计复用。其余页面记录到下方审查表，区分源码复核、已有测量和仍需测量的交互。不能据此声称九个页面均完成正式窗口的帧率验收。

苹果建议 body 保持高效并限制依赖，先测量再采用懒容器；懒布局需要兼顾尺寸估算的正确性。见 [SwiftUI 性能文档](https://developer.apple.com/documentation/xcode/understanding-and-improving-swiftui-performance)、[高性能滚动容器](https://developer.apple.com/documentation/swiftui/creating-performant-scrollable-stacks/)及 [WWDC25 Instruments](https://developer.apple.com/videos/play/wwdc2025/306/)。本轮据此缩减重复派生、验证实际构建数量，并对滚动位置做渲染对照。

## 会话页：外层懒容器没有覆盖工作流长卡

`SessionsView.claudeSection` 原先在普通 VStack 中构建每张工作流长卡。外层 LazyVStack 只能延迟整个 section；该 section 出现后，所有长卡仍被构建。已有普通会话 TileGrid 本身具有按需构建行为，没有必要重写。

工作流长卡现放入单列 LazyVGrid，保留外层 VStack、section 标题和普通宫格。在固定视口内，长卡首次构建量从随总条数增长变成只覆盖可见区域及预取部分。懒布局不会减少 session 数据的保存，也不能保证滚动到末尾时完全没有额外测量。

曾对照直接把内层 VStack 换成 LazyVStack：虽减少构建，但混合长卡和普通宫格时，程序滚动到交界附近会出现明显位置偏移；因此未采用。最终单列懒网格通过三个数据场景的顶部、中段、目标 998 渲染对照。混合场景按偶数 ID 分配长卡，目标 998 是长卡末尾与普通宫格的交界，不能把它描述为整页最后一条普通卡。

## 模型页：端点归属的准备和查询分开

`ProviderCatalogEntry.matchingAll` 原先每次输入都遍历目录并规范化每个候选端点。现在公开、不可变的目录端点只在静态索引首次使用时准备一次；每次查询只规范化用户输入，再查字典。目录顺序、同一条目的去重和 `matching` 对 Coding Plan 的优先级均保持原语义。

索引空间与公开目录端点数有关，不保存用户输入。第一次准备仍有遍历、URL 解析及分配成本；本轮单独列出的 2,000 次查询指标是在索引预热之后测量。

`ProviderCatalogBrowser` 保留一份分区结果，键是完整 `[Provider]`。余额、选择、搜索变化复用端点归属；名称、URL、catalogID、认证字段、模型列表和其他 Provider 字段变化均失效，因此卡片不会拿到旧值副本。此缓存属于挂载页面，不发布额外状态，不引入异步占位或全局用户配置缓存。

## 连接器页：避免同一目录在局部 UI 更新时重复扫描

`ConnectorInventoryCache` 每种派生只保留最新一份：记录过滤与排序、本机 CLI 过滤、sharedOwner 计数。记录键包含完整 records、类型、平台、修剪后的搜索词、locale，以及非空搜索时的插件内容。CLI 搜索沿用原有未修剪的字符串语义；只有本机页签才计算 CLI 列表。空搜索不依赖插件内容来决定记录入选，卡片仍直接读取最新内容。

归属计数由每张 CLI 卡片遍历全目录，改成目录变化时一次聚合，再按名称取值。首次准备从 C × R 次记录访问变成 R 次聚合和 C 次查询。重复未变数组使用 Swift 值语义和共享存储的相等比较；若输入是重新分配但内容相等的数组，相等比较仍可能是 O(R)。因此不能把所有状态下的缓存检查一律称为 O(1)。

过滤排序与分区同样在输入变化时重新执行。所有缓存有界，但保留输入和派生值，不能称为内存占用下降。选择、确认框、批处理进度等局部 UI 更新复用准备好的派生，不把这些临时状态加入目录键。

重复派生的计数在第一次准备后清零，故零表示预热后的复用，不表示从打开页面起从未工作。归属微基准显式查询全部 200 个 CLI，不表示界面同时显示 200 张卡片。分区的极短耗时含优化编译下的循环、键比较和读结果，不能当作一次 SwiftUI body 耗时。

原生会话夹具使用真实 section、TileGrid、EqualRowGrid、NSHostingView、ScrollViewReader；卡片内容和外围 Theme/标题是固定 160pt 的测试替身。宿主初始耗时包含 20ms RunLoop 等待、字体/框架准备、图像栅格化和 PNG 摘要，不是正式应用页面打开耗时或 FPS。普通宫格没有生产变化，耗时略增，不能宣称这条路径加速。

每组三个场景 × 三个滚动位置的九份像素摘要与基线相同；滚回顶部恢复原图，可见标题更新确实重绘。另补查 120–288pt 静态不同高度的卡片：九份摘要中八份相同；混合交界处长卡图像相同，普通宫格整体向下相差一个物理像素（该宿主为 2×，即 0.5pt），平移后内容完全相同。这项布局舍入差异保留记录，不能称为九份全部精确匹配。仍未覆盖真实工作流卡内的 ViewThatFits、实时高度变化、编辑焦点和所有主题。

连接器测试对照 160 组类型/平台/搜索组合，使用冻结的独立过滤语义；验证记录启停、改名、平台、归属、插件内容、增删和空目录失效。模型测试对照 369 个实际目录 URL 变体，验证顺序、去重和 Coding Plan 优先级，并比较 Provider 完整字段修改、增删、顺序和空列表之后的分区。测试不读取用户配置、不扫描真实外部客户端。

## Instruments：相同合成工作负载的主线程热点

两臂均用 Time Profiler 模板，重复派生循环增加到 240 次，程序自然退出。未修改正在运行的正式应用。一次前采样、一次后采样结果如下。

| 整段采样指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 主线程 sampled CPU 权重 | 15,250 ms | 1,614 ms |
| Foundation inclusive 权重 | 5,783 ms | 740 ms |
| SwiftUI inclusive 权重 | 413 ms | 63 ms |
| SwiftUICore inclusive 权重 | 426 ms | 65 ms |
| AttributeGraph inclusive 权重 | 354 ms | 44 ms |
| 首个项目帧：identityURL | 5,204 ms | 277 ms |

权重是采样 CPU 累积，不是进程墙钟耗时；inclusive 项彼此重叠，不可相加。采样含初始化、独立 oracle、失效验证、原生容器、图片摘要和预热重复派生，因此不能将整个变化归因于某一张真实卡片。采样中缺失 backtrace 权重分别 16ms、13ms，项目帧未符号化分别 110ms、2ms；导出引用均解析完成。

本轮没有采集 SwiftUI body 时长、GPU 合成、hitch 或真实窗口 FPS，不把空的 hitch 表解释为零卡顿。原始 trace、仅 time-profile 表的 XML、合成源和图片位于 gitignored、0700 的 `.build/performance/page-frontend-2026-10-05/`。录制环境以 `env -i` 清空，仅传 PATH、TMPDIR；公开 JSON 只保留指纹与聚合数据。
