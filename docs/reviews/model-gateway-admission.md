# 网关供应商并发与队列验证

日期：2026-10-10。范围：第三方 Auto 网关及启用「接管全部第三方请求」后的网关请求。沿用现有 actor、私密持久化、协议适配与原生设置组件；其他客户端的普通转发流程保持原路由。

## 行为与所有权

- 全局默认 4 个、每供应商配置默认 2 个并发，按 UUID 共享该配置下所有模型，可单独覆盖。预留、释放和队列调度在同一 actor 中原子完成。
- 全局队列默认 32 个，每配置默认 8 个，等待默认 30 秒；等待正文合计限制 64 MiB。默认值与上下界均由生产配置校验，旧版文件补入默认值而不改凭据引用。
- 最早可运行请求先执行，繁忙队首可让其他兼容供应商继续工作；备用等待会重选刚空闲的剩余候选。排队不占全局／供应商执行额度，不计入 RPM，不制造连接／输出阶段。
- 流式尝试持有额度直到完成、失败或取消。结束上游传输后才报告和释放；备用等待不占全局执行额度。成员 ID 与请求 ID 标识所有权，重复收尾和迟到结果不能释放别的尝试。
- 客户端断开会取消专属转发任务及其上游；URLSession delegate 显式捕获取消句柄，不依赖回调线程中的 task-local。取消／超时只处理自己的等待；配置变更或停用取消旧等待，现有执行额度保留直到真实结束。
- 队列满为 HTTP 429／gateway_queue_full，超时为 504／gateway_queue_timeout，带 Retry-After: 1。RPM 仍独立计数备用尝试，额度用完立即返回 429。

## 验证

- 全量隔离快照 `make test`：100 组通过，619.79 秒。这是最后的响应头前取消句柄修正之前的全量结果。
- 最终生产源码 `make test TEST=free-model-gateway`：通过，71.10 秒。覆盖共享供应商多模型额度、空闲供应商选择、FIFO、全局／供应商／字节容量、撤队／超时、全局额度释放、备用转移／动态重选、并发账户冷却、上限调低、配置变更、shutdown、40 请求竞争及旧文件兼容。
- 实际本机 HTTP 上游验证鉴权与三协议、真实排队、429／504／Retry-After、无排队上游扣次、等待客户端关闭、响应头前客户端关闭、流式断开及后续额度复用；原有 401／429 回退、首帧失败及中途不重试继续通过。
- 原生探针通过空闲／输出／终态、减少动态效果与 detach；200 模型视口挂载 3 行，12 次输出更新重绘 0 行。当前浅深色并发设置截图已检查，数值与恢复默认槽位保持对齐。
- 最终 dev／release 构建均通过，bundle／Widget／URL scheme／entitlements／签名验证通过。未安装或启动主应用。
