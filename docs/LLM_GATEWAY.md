# Auto 免费模型网关

入口：**模型 → 自动网关**。供应商目录和 Claude Code / Codex 的激活流程保持独立。

Auto 在未指定难度时，通过本地规则判断用户任务的类型和难度，再结合模型池能力与运行健康状态选择模型。规则基线不增加外部模型调用；语义分类器、任务质量评测与会话黏性仍属于后续设计。Cursor 等方案的调研见 [模型任务路由](technical/llm-model-routing.md)。

## 接入

1. 在供应商目录保存连接凭据。已有 Claude Code / Codex 供应商都能作为候选；Claude Code 的地址使用现有 `ProviderBridge` 转换到 OpenAI 兼容接口。
2. 在「从已有供应商提交」选择供应商和模型，确认免费资格、上下文长度、工具／图片／JSON 能力，加入 Auto 池。网关使用该供应商的 Chat Completions 接口，供应商本身需要支持此接口。
3. 打开 Auto 和设置里的本地代理。第三方客户端填写设置页所示 Base URL、本机 API Key，以及模型名 `auto`（也接受 `claudebar/auto`）。Anthropic 客户端使用同一监听地址的 `/v1/messages`。

默认只接管第三方的 Auto 请求。显式模型名继续走原上游，Claude Code / Codex 请求仍走各自配置。可选「接管全部第三方请求」会覆盖第三方显式模型名。网关不开启时 Auto 返回明确错误，避免落到其他上游。

「记录第三方流量」决定是否在流量页保留请求正文；每次备用尝试会显示实际供应商和模型。本次运行最近 40 次路由尝试的状态、模型与延迟始终可在网关页查看，不包含请求正文、密钥或账户信息。

## 按任务难度路由

客户端只需设置 `model: auto`。未传难度时，网关读取最近的有效用户目标，通过本地规则判断 low / medium / high；无法明确判断时保守采用 medium。顶层字段 `task_difficulty` 保留为可选覆盖，取值为 `low`、`medium`、`high`，传入后优先遵守客户端指定档位。Chat Completions、Responses 和 Anthropic Messages 使用相同字段；无效取值返回 HTTP 400。它只用于网关选模型，在发给上游前删除，不修改上游的推理强度参数。

```json
{
  "model": "auto",
  "messages": [{"role": "user", "content": "排查偶发死锁"}]
}
```

规则覆盖问候／连接检查、提取／翻译／转换、常规编码／写作，以及复杂排错、系统设计与多步推理。长原文的转换任务不会仅因长度或原文包含复杂术语升档；系统提示和工具输出不作为任务指令。“继续”与工具续轮参考已有用户目标，自动判断的工具任务至少采用 medium。新用户目标重新判断。当前规则以常见中文／英文指令为主，不是训练过的语义分类器，不提供未经评测的准确率保证。

自动判断的档位没有兼容模型时，可依次升到更高档位，绝不自动降档；显式指定难度始终严格匹配。匹配档位已有模型但正在冷却时仍返回冷却错误，不靠跨档位切换规避冷却。状态页显示任务类型、实际档位、规则／客户端指定／兜底来源，以及升档与选模原因，不保存用户原文。

模型池每个条目可直接勾选低／中／高难度，可多选；手动加入时也能设置。新模型和旧配置中未保存难度的模型默认承接所有档位，随后可按需要收窄，例如轻量模型只承接 low、强模型只承接 medium / high。目录刷新保留手动设置。

网关先确定可承接任务的难度档位，再筛选工具、图片、JSON、上下文和冷却状态，最后按所选策略排序。备用切换仍留在该难度内；没有匹配模型返回 400，匹配模型都在冷却时返回 503，不会自动降到其他档位。网关状态记录每次尝试的判断来源、难度和选择原因。显式模型名未被网关接管时仍走原路由。

## 模型池与可用性

- 均衡轮转：优先失败较少、最近较少使用的模型。
- 池内顺序：按从上到下的模型优先级选择，可在模型菜单上下移动。
- 低延迟优先：使用已观测的上游响应头耗时，尚未测量的模型先获得试用机会。
- 依据请求过滤工具、图片、结构化 JSON 和上下文容量。上下文使用保守的本地估算，不能替代模型的真实 tokenizer。
- 最多尝试 1–5 个模型；并发为 1–8；每分钟额度计入备用尝试。达到网关自身限额时返回 429。
- 429 至少冷却 60 秒，尊重数值型 `Retry-After`，最长一小时；404 / 410 冷却 30 分钟；网络和服务端故障指数退避，最长五分钟。401 / 402 / 403 暂停对应供应商五分钟，可继续选择另一供应商。
- HTTP 成功但首个 SSE 帧报错仍可切换。首次有效输出开始后不再重放请求，断流会明确结束为错误。取消不会记作模型故障。
- 「未测试」表示尚未成功使用，目录发现不代表已通过推理测试。成功、失败、冷却和缺少凭据都有独立状态。
- 修改或删除供应商会更新运行时引用，不复制凭据、不修改供应商的激活状态。手动模型可停用、移除和编辑能力。

其他平台的永久免费、赠送额度、试用资格由用户确认。网关无法为这些平台验证账单规则或保证超出免费额度后不收费；应在供应商账户关闭超额付费或设置额度限制。

## OpenRouter 发现

使用官方 [`GET /api/v1/models`](https://openrouter.ai/docs/api/api-reference/models/get-models)。默认每六小时发现一次，可改为一小时或一天；默认手动选择加入，自动加入为显式选项。目录可匿名发现，实际推理需要选择已有的 OpenRouter API Key。

只接纳有文本输出、上下文长度有效，且所有已公布价格（至少包含输入与输出）均为零的模型。`:free` 后缀本身不作为免费证据。收费变化、下架或者目录超过 48 小时未更新时，该 OpenRouter 模型不再参与路由；发现失败保留上次成功目录。推理额外设置 `provider.max_price` 的输入、输出、请求、图片、音频维度为零，删除客户端传来的模型回退列表和付费插件。

OpenRouter 的[免费路由说明](https://openrouter.ai/docs/guides/routing/routers/free-router)和[额度说明](https://openrouter.ai/docs/api_reference/limits)明确指出可用性、能力和限流受平台规则影响。跨模型切换不能绕过账户总额度，也不保证任一免费模型始终在线。

OpenRouter 使用 `require_parameters` 避免静默丢弃工具或 JSON 参数，且不发送已废弃的 `stream_options`；平台会[自动返回用量](https://github.com/OpenRouterTeam/docs/blob/main/cookbook/administration/usage-accounting.mdx)。其他 OpenAI 兼容上游仍请求流式用量。

## 协议与边界

支持 OpenAI Chat Completions（JSON / SSE）、Responses（JSON / SSE）与 Anthropic Messages（JSON / SSE）。Responses / Anthropic 使用现有协议适配器转到 Chat Completions。支持工具历史、工具调用和图片；不支持的音频、视频、服务端内建工具返回明确请求错误。Responses 的 `previous_response_id` / `conversation` 不参与无状态跨供应商路由，客户端须携带完整历史。Anthropic `count_tokens` 返回本地保守估算，不发送推理请求或消耗网关额度。

远端供应商仅允许无内嵌凭据的 HTTPS 地址；重定向不携带任何密钥继续请求。本机代理仍要求本机令牌，客户端供应商凭据不透传。模型池只持久化供应商 UUID 和模型元数据，文件通过 `PrivateFileWriter` 原子写入、权限 0600，使用 `FilePaths.freeModelPoolFile` 随 dev / release 隔离。损坏或未知版本文件保留原样，不自动覆盖。

发现任务归应用生命周期所有，离开模型页不会停掉已启用的发现计划，关闭定期发现或退出应用会取消任务。页面只有可见时每三秒读取一次路由状态，不重复发起发现。

## 验证

`make test TEST=free-model-gateway` 使用真实生产解析、策略、持久化与协议适配函数，以及临时端口上的模拟 HTTP 上游，覆盖免费价格筛选、难度自动判断／手动覆盖／保守兜底／升档／参数校验／旧配置兼容、模型能力、冷却、并发／请求额度、密钥替换、鉴权、跨供应商回退、同档位故障切换、流式首帧失败、断流不重试和三种客户端协议。测试不读取真实供应商凭据，不调用真实推理服务，也不启动应用或 VPN。
