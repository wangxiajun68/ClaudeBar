> 相关：技术文档 [性能策略](08-performance.md) · 设计文档 [刘海灵动岛](../design/10-notch-island.md)

审查日期：2026-09-24。基于当前工作区（包含原有未提交功能），不是仅审查 HEAD。

## 本轮修复

| 路径 | 发现 | 修复 |
| --- | --- | --- |
| 全端用量刷新 | 首次 `hasCachedData` 可同步打开/迁移 SQLite 或加载 JSON；普通周期切换也查询两轮相同聚合 | 缓存探测移到后台；只有重新索引时先显示缓存，再显示最终结果 |
| 流量页实时内容 | 每个 token 重排主线程 debounce；持续流可能迟迟不刷新；主线程等待数据库共用锁；每条流各自发布 | 后台 100 ms throttle；每批更新一次字典；跳过结束/删除记录，防止旧快照覆盖最终内容 |
| Popup 根视图 | 观察整个 ProviderStore/CodexProviderStore，心跳、会话、余额都牵动整个外层 | 外层只订阅配置是否存在和供应商是否为空；具体面板保持自己的观察 |
| 菜单栏网速 | 数字变化时重新生成相同图标 | 复用图标 |
| 灵动岛用量 | generation 只能丢弃旧结果，不能阻止同时启动多批聚合查询 | 一个在途任务加一个合并后的尾随刷新 |
| 桌面遮挡 | 收到遮挡通知却只检查 isVisible | 同时检查 occlusionState |
| 跨窗口动效 | 任一窗口可见会使隐藏主窗口的风扇、能源流、装饰动画继续运行 | 所属 surface 的可见性经环境传递；同时补上部分装饰动画的 Reduce Motion 限制 |
| 设置页 | `presentFiles` 是计算属性，每个文件卡片可能重复扫描目录 | 后台扫描，最多每 5 秒更新一次，关闭页面取消；按完整 URL 判断文件 |
| 等高网格 | 实时缩放产生大量不同宽度的测量缓存 | 最多保留 8 个 proposal 的测量结果 |
| 原始 JSON | 取消的解析任务仍可回写；默认 ID 仅按字符串长度判断 | 取消后不发布；无显式 ID 时按内容更新 |

本轮没有移除页面切换、弹簧、hover、灵动岛展开等效果，也没有通过降低交互刷新率优化。

## 静态检查覆盖与保留的实现

- 主窗口：导航按需挂载页面；流量页状态与页面生命周期分离。
- 概览：LazyVStack；硬件采样由共享 sampler 提供。
- 会话：会话网格使用 LazyVGrid；popup 使用 LazyVStack；子智能体展示有可见数量上限。
- 模型与编辑器：检查目录搜索、图标缓存、模型获取和供应商切换路径；网络请求已有异步任务。
- 用量：聚合后台执行；年度热图使用 Canvas；本轮减少重复查询。
- 流量与日志：列表虚拟化；大文本使用 NSTextView；JSON 后台解析；本轮修复流式发布热点。
- VPN：检查列表、日志、实时速率和启动动效路径；本轮按所属窗口暂停装饰动画。
- 设置与帮助：检查滚动容器与同步文件调用；设置目录扫描已移出 body。
- Popup：关闭时销毁 hosting view，避免隐藏 SwiftUI 图持续工作；本轮隔离根视图观察范围。
- 灵动岛：面板固定尺寸，状态转换保留弹簧；会话摘要去重；本轮合并后台用量查询。

这是路径级静态审查，不代表逐个函数的耗时已经测量。高频 ProviderStore 仍有多个整页观察者，极端数据量下需要用 Instruments 确认其实际成本，再决定是否进一步拆分。

## 自动验证

`make test` 包含原有 UI/核心回归，以及新增 `Tests/performance-regressions.py`。

新增测试从生产代码提取调度方法，使用隔离的 Combine fixtures，不读写用户数据库：

- 100 路模拟流、持续推送时仍周期发布，不等待流结束。
- 每个批次只发一次 streams 和 previews 通知，而非每条记录一次。
- 结束或删除后，延迟批次不再覆盖/恢复记录。
- 后台持有数据库共用锁时，主线程探针仍能执行，刷新不阻塞交互线程。
- 101 次灵动岛刷新请求合并成 2 个串行计算；最大并发为 1。
- 完成后释放刷新门，下一次请求仍能执行。

完整应用验证使用 `CLAUDEBAR_SKIP_INSTALL=1 CODESIGN_IDENTITY=- bash Sources/build.sh`，生成本地优化构建，不替换 /Applications 中的应用。

## 帧率验收边界

另对当前运行的 `/Applications/ClaudeBar.app` 做了 3 秒 `sample` 调用栈采样，观察到 SwiftUI/Core Animation 的布局与绘制工作。该进程没有加载本轮修改，因此这只是旧版本的现场线索，不能作为优化后数据或前后对比。

本机仅有 Command Line Tools，`xcrun xctrace` 不可用。自动回归验证的是调度、通知数量、取消与布局行为，**不是 GPU 帧率、真实滚动 hitch 或功耗测试**。不能据此声称全端绝对无掉帧。

有完整 Xcode 的机器应使用 Release 构建和 Instruments 的 Time Profiler / Animation Hitches，分别测量：

1. 冷启动与再次打开 popup；三端同时显示。
2. 各页面连续往返切换、快速滚动和连续窗口缩放。
3. 100 条会话、多子智能体、年度用量、多模型卡片。
4. 多路持续流、大 JSON/SSE、实时日志与 VPN 流量。
5. 主窗口遮挡/最小化，同时展开 popup 或灵动岛；关闭后检查 CPU/GPU 回落。
6. 浅色/深色、Reduce Motion、60 Hz 与 ProMotion、低电量模式。

记录主线程与渲染耗时的 p50/p95/p99、hitch 次数、峰值内存、关闭后 CPU。60 Hz 每帧预算约 16.67 ms，120 Hz 约 8.33 ms；数据更新 10 Hz 不等于显示刷新 10 FPS。装饰 TimelineView 中仍有 12/20 Hz 采样，这些效果的平滑度应单独验收，不能用页面平均 FPS 掩盖。
