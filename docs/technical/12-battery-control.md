# 电池充电控制

> ClaudeBar 技术文档 · §12
> 相关：设计文档 [产品概述](../design/01-product-overview.md) · [文件结构](../design/07-file-structure.md)

能源卡片支持 20–100% 目标（默认 80%）、自动管理、充电至目标、接电放电至目标和恢复系统管理。未启用时调整目标只保存偏好；启用后自动提交，界面分别显示目标值与已生效值。多个入口共享一个控制器。

## 控制行为

- 自动管理：高于目标时主动放电，到目标后停充并恢复适配器供电；低于目标 2 个百分点再允许充电，避免读数抖动反复启停。
- 充电：允许充电到目标，再按滞回保持；高于目标时仅停充，不主动放电。低于 20% 时允许充电。
- 放电：禁止充电并断开适配器输入，降到目标后转为自动管理。未接电时不主动断开输入，接电后继续管理；目标已达到时直接转自动管理。
- 不支持主动放电的机型退化为仅限充，界面说明无法主动降到目标；手动放电按钮禁用。
- 合盖、休眠：结束主动放电。休眠通知到达时恢复原始控制值，再允许休眠。唤醒后恢复充电上限控制，主动放电保持暂停，可点击模式按钮或调整目标恢复。**休眠期间不承诺保持上限。**
- 状态文字区分“指令已确认”和“实测电池状态”。SMC 回读一致不等于真实电流已经改变；系统、温度、电池和适配器仍影响物理充电。
- 退出应用通过管道 EOF 交回系统；退出清理回报不覆盖用户保存的管理模式。下一次应用启动主动探测并恢复已授权的管理模式，不依赖界面出现。工具需要重新授权时明确显示待恢复，授权成功后继续恢复。

## 同步与反馈

所有操作共享一条请求通道，最多一条命令在途。滑杆、键盘和辅助功能调节都更新最新意图；收到当前回执后再提交最新目标，不会把旧模式附带进新的阈值操作。还原系统可覆盖在途操作，之后的目标修改只保存，不重新启用管理。

每条命令有 8 秒响应超时；运行期间也检查状态新鲜度。应用使用 common RunLoop 模式每 2 秒发送 heartbeat，避免普通菜单跟踪暂停默认模式 Timer。失联时关闭输入、请求恢复系统，并清除“已生效”显示。终态恢复失败继续保留明确告警。旧 revision 和旧进程回报不能覆盖当前状态；成功回执清除已解除的普通错误。

helper 无命令时每 2 秒评估；新命令使下一轮立即评估（循环等待约 250ms，加硬件调用时间）。有效状态回报触发一次独立电池采样，刷新能源图和实测说明，不受资源采样慢档/暂停影响。指令与电流不一致时先显示等待变化，持续超过 10 秒明确提示检查电源状态。

## 实现与权限

`Sources/batteryctl/batteryctl.c` 是独立 C 辅助进程，`--probe` 只读，`--serve` 需要 root。仅接受四种模式、20–100 阈值、请求版本号和 heartbeat；不提供任意 SMC key、路径、shell 或网络接口。

用户可先在「设置 → 权限与隐私 → 辅助工具」完成系统管理员授权，也可首次点击控制按钮时授权。随包签名的工具安装到 `/Library/PrivilegedHelperTools/com.claudebar.batteryctl`，root:wheel / 4755；匹配当前应用包时后续启动直接复用，无需再次确认。应用更新了辅助工具后会要求重新授权安装新版。安装采用 root 目录中的临时副本，校验 SHA-256 与代码签名后再设置权限并替换。运行前校验安装副本归属、文件类型、权限和内容与当前包一致。没有 launch daemon；应用通过私有 stdin/stdout 管道与工具通信。授权取消只显示错误，不启用控制。

辅助进程持有 `/var/run/claudebar-battery.lock` 排他锁；启动时遇到已有非零充电控制值会拒绝接管，提示先关闭其他电池工具。其他工具在运行期间重新写入不受 ClaudeBar 控制，因此不要同时启用多个限充工具。

每 2 秒读取电池并评估策略；每次写入后回读确认；状态带请求版本、降级说明和退出标志，界面等待确认。应用每 2 秒 heartbeat。管道 EOF、20 秒失联、无效命令、传感器异常、SIGTERM/SIGINT/SIGHUP 都进入恢复路径。部分写入失败时先恢复适配器，再恢复充电控制。恢复失败会明确提示，不能保证 SIGKILL、系统崩溃或固件故障下自动恢复。

## SMC 兼容性

优先 CHTE（4 字节；禁止充电 01 00 00 00）；否则需要 CH0B 和 CH0C（各 1 字节；禁止充电 02）。主动放电按 CHIE（08）、CH0J（01）、CH0I（01）顺序检测。恢复值来自启动时的原始状态，仅接受全零正常状态作为接管起点。所有 key 由程序固定列出，核对长度，不探写未知 key。使用项目现有 80 字节 AppleSMC 协议，并完整回传 key metadata。

机型能力只读检测成功不等于硬件写入已经验证。未检测到充电 key 时禁用全部控制；无放电 key 时仅禁用主动放电。

## 验证

```sh
clang -Wall -Wextra -Werror Tests/battery-control.c -framework IOKit -framework CoreFoundation -o /tmp/claudebar-battery-tests
/tmp/claudebar-battery-tests
CLAUDEBAR_SKIP_INSTALL=1 CODESIGN_IDENTITY=- bash Sources/build.sh
```

运行 `python3 Tests/charge-limit-regressions.py`（也已包含在 `make test`）会执行控制器交互测试和 C 测试。控制器测试覆盖目标回拖、模式竞争、系统还原、授权期间改值、失联、旧回报、休眠和偏好保存。

测试将生产辅助进程的 IOKit transport 替换为内存模拟，覆盖阈值范围、滞回、20% 保底、严格命令解析、无重复写入、部分写入回滚、恢复失败、缺少放电能力和休眠恢复。不会安装特权工具或修改真实 SMC。
