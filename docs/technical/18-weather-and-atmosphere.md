# 天气与天空渲染

> ClaudeBar 技术文档 · §18
> 相关：[视图层](05-view-layer.md) · [性能与并发](08-performance.md)


本模块负责问候卡的天气数据、当地时间、太阳事件、天空场景、文字排版与动态渲染。界面意图见 [问候天空设计](../design/greeting-atmosphere.md)，跨模块负载边界见 [性能与并发](08-performance.md)。

## 模块职责与数据流

| 组件 | 职责 |
| --- | --- |
| `WeatherStore` / `WeatherFetcher` | 按订阅与刷新策略取得当前位置或指定城市的天气，保留最近读数 |
| `WeatherForecastFetcher` | 将来源预报规范为 `WeatherReading` 与 `WeatherDay`，保留真实坐标、时区和每天的绝对事件时间 |
| `SkyAstronomy` | 根据 UTC 时刻和经纬度计算太阳、月亮和恒星位置；按当地日期求太阳地平线交点 |
| `SkyScene` | 将天气和天文位置映射为云、降水、亮度、风与场景参数 |
| `GreetingCard` | 选择当前/预报日期、自动/手动模式，管理时间拖动、天气订阅和可见性 |
| `GreetingInstruments` | 天气读数、日轨、预报、时间轴与手动选择器 |
| `GreetingScript` | 字体轮廓、问候与姓名布局缓存、文字纹理栅格化 |
| `AtmosphereRenderer` / `AtmosphereShader` | Metal 缓存层与最终合成；`WeatherBackdrop` 提供不可用时的原生回退 |

天气读数是数据来源，渲染开关只控制效果与刷新。已有读数的经纬度和时区在手动模式或关闭动态天气后仍有效；不应因这些开关把太阳事件改成固定时钟。

## 当地日期与日出日落契约

`SunPath.times(on:reading:zone:)` 按所选日期和地点时区解析，返回两个可选绝对时间：

1. 对应 `WeatherDay` 的日出/日落时间优先，保留来源的绝对时间。
2. 没有对应预报日时，可解析读数中的 `HH:mm` 或 `hh:mm AM/PM`，但仅限 `observedAt` 与所选日期属于同一个当地日。格式、小时和分钟必须有效，不能截取任意数字或钳制坏值。
3. 仍有缺失且拥有有效经纬度时，使用 `SkyAstronomy.solarEvents` 计算该地点、该日期的事件。没有可靠位置时保持缺失，不用设备时区推测经度，也不用假定纬度填事实标签。

太阳事件使用标准视地平线 −0.833°，包含常用折射与太阳半径修正；约定见 [NOAA 太阳计算公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)。实现复用现有低精度太阳星历，在 `Calendar.dateInterval(of: .day)` 给出的当地日内分段寻找高度符号变化，再二分收敛。它是无网络的天文估算，来源预报仍优先；不包含地形遮挡、实时大气折射，也不作为导航级计算。五分钟扫描间距在极圈附近可能漏掉极短的日照窗口。

日期边界由地点时区的 Calendar 决定，支持夏令时的 23 / 25 小时日。日出/日落快捷按钮定位到解析后的真实事件时刻，不附加展示偏移。时间轴的分钟是当地钟表的小时、分钟和秒，不是从零点累计的秒数；手动日期按当地时钟构造。日轨夜间邻日边界也用日历加减日，而非固定 86,400 秒。

结果按当地日、时区和经纬度缓存，最多 32 项，访问受锁保护。天气来源已有事件时无需求解；相同日期内拖动、重排或切换天气命中缓存，没有逐帧太阳事件扫描或新增 timer。

没有事件时，标签显示 `—`；日轨不绘制虚构的太阳/月亮进度，时间轴不显示缺失事件的刻度。依赖一整段日照区间的时段快捷按钮禁用，整日时间轴仍可拖动。极昼极夜允许事件为空，不能兜底成 06:00 / 18:00。

## 场景问候与小时预报

`GreetingPhrase` 使用两小时内的真实天气读数与本机时段：普通雨天提示热茶与休息，17–21 时提醒带伞和慢慢回家；大雨、雷雨、冰雹使用更谨慎的出行提醒。节日保留祝福标题，同时显示天气关怀小字；22 时后仍优先休息。英文界面也使用天气文案。手动贴图和模拟天空不会伪装成用户所在地天气。

右上角的 `HourlyWeatherInstrument`（宽卡片与日预报同高 80pt、窄卡片 60pt）只取当前时刻之后六小时内的来源桶。降水优先，缺少雨量但有概率时单独标注 `%`；无降水且预报风速达到 28 km/h 时展示风速，其余展示气温。降水量是各标注时刻前一小时累计值（mm），不是概率换算或分钟级临近预报。峰值 / 温度范围与图使用同一组数据；悬停和 VoiceOver 可读每个时刻的数值与来源。缺失值保留缺口，过期或无小时数据时显示暂不可用。

Open-Meteo 主预报请求带小时字段；国内源成功后按已有经纬度额外取 Open-Meteo 小时预报，保留国内当前实况与日预报。补取失败保留实况，不补造小时数据。请求沿用现有刷新周期与临时 URLSession，无新增常驻轮询或系统定位授权。字段契约见 [Open-Meteo 文档](https://open-meteo.com/en/docs)。

## 渲染分层与降水

Metal 将低频天空与高频交互分离：渐变、天体、卷云、体积云和雾缓存为半分辨率天空纹理；雨雪使用一次烘焙的底片；最终通道合成天空、降水、闪电、字形和玻璃水滴。云层不随每次文字、视差或拖动帧重新计算。

雨纹理是随机长短的短尾、渐细轮廓和亮头，使用矩形底片的真实尺寸采样。远、中、近层具有不同速度、透明度和形态，通道独立下落；雷雨增加密度、速度与轻微阵风，闪电继续影响云层。没有逐雨滴 SwiftUI 视图、动态 CPU 粒子数组或额外粒子引擎。Canvas 回退保留短雨线、速度与长度差异。

静止天空采用受限帧率，交互、字形入场和淡变阶段才请求更高刷新率；低功耗与热压力降低云层更新。具体档位由 renderer 的帧率策略集中管理。Reduce Motion、所属 surface、窗口遮挡、局部视口和页面滚动共同决定播放/定帧，拆卸释放观察者与回调。

暂停显示循环后，AppKit 仍可能交付已经排队的 redraw。`AtmosphereMTKView` 在 `kick` 和 `draw(in:)` 再次检查 active、窗口可见性、滚动定帧与 Reduce Motion，检查通过后才获取 drawable；停用不再请求额外 redraw。

Reduce Motion 的静态天空由 `StillCache` 按输入、几何尺寸和 display scale 缓存。实际卡片通过 `.task(id:)` 在串行 Dispatch 队列等待 GPU 并回读图片，主 actor 只接收最新且未取消的结果；新图片就绪前保留已有图片。取消的排队尺寸跳过渲染，失败不记录缓存键；离屏或停用不生成快照。同步路径仅供 `AtmosphereSurface.stills` 的 ImageRenderer 工具捕获使用。

## 文字、对比度与布局

信息区域按各自条带的局部天空亮度独立选择高不透明度白字或深墨字（`SkyScene.prefersDarkInk(at:aspect:)`）；最终 Metal 通道只做暗角、窗台沉降、深色外观曝光与入场淡入，没有为读数区域合成底色或渐变遮罩，也没有新增模糊或额外绘制通道；SwiftUI 回退里问候与姓名改用场景的整体墨色（`scene.prefersDarkInk`），信息区域仍走同一分区规则。

设置 → 天气与问候 → 问候语支持自动、日常问候与固定短语（你好呀 / 早上好呀 / 下午好呀 / 晚上好呀 / 晚安好梦 / 欢迎回来 / 慢慢来就好 / 你好，本月）、诗词与自定义（最多 80 字，留空回到自动）。选择与自定义文本使用当前版本的 `UserDefaults.standard` 保存。自动模式继续按时段、节日和天气选择，普通日子改从**当季节气或季节**摘一句古典诗词（中文）或公共领域英文诗（英文）；「日常问候」保留最基本的日常话语（早上好、早点休息一类），按时辰轮换、不引用诗词；「诗词」只看节气与季节，忽略节日和天气。固定和自定义内容不随天气变化，语言切换作用于内置文案。

节气是离线的日历数据：`SolarTerm.swift` 提交 2026–2030 的公历日期（香港天文台年历，与 NOAA 视太阳黄经 `285°+15°·k` 的跨越时刻一致），`term(on:)` 给出当天节气，`season(on:)` 以立春/立夏/立秋/立冬划分四季。年份超出窗口时复用最近一年，不臆造日期。

中央问候根据场景亮度选择墨色。姓名保留用户大小写，使用系统圆体 medium，18–28pt、0.015em 字距和完整墨量。问候字体仍服从用户偏好；布局使用实际字形边界、负 bearing 和描边宽度，在上下仪表之间限制高度，并求出能够完整容纳问候与姓名的最大字号。宽度至少 900pt 时，小时图位于每日预报左侧，问候上方仅保留 88pt 天气区；较窄窗口为上方小时图保留 156pt。姓名独立成一行落在问候语下方（`nameInline = false`），右端对齐问候墨迹并受横向边界约束。

布局缓存与后台纹理栅格化分开管理。姓名、文字、字体或尺寸变化才使相关缓存失效；不要把静态字形轮廓或阴影重新放入每帧计算。

连续调整尺寸或短语时，栅格化完成的键必须仍等于最新请求才安装纹理、通知视图；过期结果直接转入最新任务，期间保持已有纹理。

## 验证与维护

- `make test TEST=greeting-layout`：编译生产布局与太阳事件解析；覆盖 5,300 个字体/宽度/问候/姓名组合，以及季节、经度、日期、预报优先级、缺失/坏时钟、极昼极夜和夏令时。
- `make test TEST=solar-term`：编译生产 `SolarTerm`，用香港天文台 2026–2030 的节气日期逐条比对，验证季节边界、表外年份复用与中英文诗句长度。
- `make test TEST=weather-astronomy`：来源数据解析、时区、部分预报、太阳方位、月相与恒星位置。
- `make test TEST=weather-card-performance`：生产 Metal 视图的暂停/遮挡/卸载绘制入口，静态图片一致性；模拟阻塞后端验证后台所有权、排队取消、失败重试和最新结果；文字纹理过期结果丢弃。使用不可见合成窗口，不启动 ClaudeBar 或请求天气服务。
- `make test TEST=dashboard-performance`：概览最多格式化六条可见会话，验证三种来源优先级、完整计数和等待状态。
- `python3 Tools/render-greeting-preview.py --weather-review`：合成天气数据与临时偏好，生成宽/窄卡片、自动/手动场景；不读取真实账号或发天气请求。
- `python3 Tools/bench-atmosphere.py --frames 120 --contrast`：从当前卡片提取 Metrics，测量生产着色器 GPU 成本、字形栅格化与信息区域对比度，输出逐天气 METRICS JSON 和确定时刻图片哈希；可用 `--baseline-ref REF` 编译指定源码基线。对比度按实际 sRGB 背景与 `SkyScene.prefersDarkInk` 选中的墨色（86% 覆盖）取样，时钟、当前天气、日轨、每日预报、小时预报五个区域各自取**中位数**门槛 3:1，并打印每场景最差单像素。该工具阈值不能证明小字号文本满足 4.5:1，也不代表全部字形边缘或所有过渡帧。
- 交付运行 `make test` 和 `make build`；发布构建用 `make release`，不会自动安装或启动正式版。

工具产物位于 `.build`，历史机器读数保存在 [测量证据](../reviews/weather-card-measurements-2026-09-30.md)。GPU 微基准不能证明整窗口的显示帧率或整机能耗，需按 [性能模块的测量契约](08-performance.md#验证入口与测量契约) 单独验收。
