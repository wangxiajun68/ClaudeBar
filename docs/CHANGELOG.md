## [Unreleased]

### 新增

- **更温暖的动态问候**：默认中文，按当地时段、节日、周末和近期天气选择问候；深夜优先提醒休息，同一小时保持稳定。支持中英文切换；移除问候下方的小文案，主文字按实际字形边界尽量放大，短句放大、长句缩小。农历节日按日历计算，母亲节和父亲节按星期推算，不再依赖两年的固定日期。
- **创意字体选择与管理**：提供 14 款中文、39 款英文字体，涵盖圆润粗体、马克笔、行草、复古招牌、泡泡字及立体轮廓等风格。设置中的字形预览默认折叠，支持名称／风格搜索、删除和恢复；删除当前字体会自动选择同语言可用字体，每种语言至少保留一款。删除实际清除应用本地字体库中的文件和字形缓存，恢复从随包原件复制；系统自带字体不提供删除，已签名安装包保留恢复资源；授权与固定版本来源随资源附带。

- **天气渲染可以关掉**：此前的天空是按实时天气画的——云、雨雪、雾、闪电、玻璃上那层水，全都在一帧里。设置 → 天气与问候新增「天气渲染」开关，关掉之后这些**天气图层**不再绘制，只留一片按太阳高度角连续插值的天空：暖冷明暗仍跟着一天走，日月照落，但不再下雨、不再飘云，也**不再联网取天气**（`greetingWeatherRendering` 一关，卡片连 `notes` 都不查）。这不是把整片天抹平成一块色板，也不是「多云动画」那种折中：关掉的是天气，天空本身还在呼吸。
- **右侧那半张卡片跟着换读法**：天空没有天气时，右上不再是「到某地的实时天气」，而是一个**贴图说明**——地点名 + `贴图` 两个字。预报带（那是读数自己的未来）与体感 / 湿度 / 风（那是读数自己的现在）随之让位；日轨留下，但它改从**本机时区**的日出日落推算（`SunPath.times(reading: nil)` 走的是 `estimatedAstronomy` 已有的那条路径），所以它不会指着一个并不在屏幕上显示的城市。窗台、时钟、问候语不动。
- **时钟下面多了一格「贴图」**：天空模式控件从此前的 自动 / 手动 两段扩到两段或三段——第三段**只在天气渲染关掉之后出现**，它本身就是再把渲染打开的开关。这一段只在偏好关掉时才占位置，所以平时的 自动 / 手动 宽度与命中区一个像素没动。

### 变更

- **天气卡片雨效与可读性**：雨滴改为远、中、近三层短尾亮头，不同通道具有独立下落速度；雷雨增加降雨密度、下落速度与阵风。四角的信息区域增加固定对比度底色，小字提高不透明度；问候语更早切换到深墨，姓名采用更大的系统圆体并保留原大小写、缩小字距。修复窄卡片中长姓名与高挑字体的布局边界。保留 Metal 预烘焙与原有节流、屏外暂停策略；没有新增逐雨滴视图或 CPU 粒子系统。

- **真实日出日落**：问候卡优先使用所选当地日期的预报事件；缺失时按已有经纬度与日期计算并缓存，不再填固定时钟或把当天字符串套到其他日期。缺数据或极昼极夜保留空事件，时间轴与快捷时段同步响应；夏令时按当地日历处理。实现契约见 [天气与天空渲染](technical/18-weather-and-atmosphere.md)。
- **技术文档按模块维护**：性能策略与天气架构分别归入对应模块，历史审查和实测证据迁入 `docs/reviews`，文档索引与引用同步更新。
- **降低隐藏界面负载**：无可见窗口时暂停资源归因采样和风扇轮询；装饰、能源流、读数扫光、旋翼及问候时钟移出视口后暂停。滚动更新门按视图记录状态，避免多窗口互相提前释放；JSON/SSE 与 Skill Markdown 预览支持后台取消，SSE 只保留并解码最后 400 条。合成 3 万事件的解析中位耗时约 305 → 74 ms，进程峰值内存约 114 → 64 MiB；测量口径与未完成的实机帧率验收见 [审查记录](reviews/performance-audit-2026-09-30.md)。

- **「自动」之外还能只换天气图层**：天气渲染开着时，手动模式里选一层天气看到的**不只是调色板**——它是真的雨、真的云。为了让这件事可做，手动控制台在两种模式下语义不同：常规手动选天气改的是「天空长什么样」，预演时选的是「只换这一层天气、时刻仍是此刻」。切进预演不闪（时刻、日月、窗台、科目都留在原地），切出预演回到实时天空。挑哪一层天气存在 `greeting.pinnedWeather` 里（`none` 即跟随实时读数）。
- **固定天空的问候语用天空自己的亮度选墨色**：`prefersDarkInk` 说的是问候语背后的地面有多亮。没有天气的天空是一片偏灰的调色板，拿它去和「实时读数」比较会让问候语在白字与深墨之间来回跳，所以这一档就直接量那片调色板自己。

- **自建的供应商地址不再被 VPN 绕出国**：供应商端点若是自建 / 只挂着自己域名的，它在国内**却命不中 `GEOSITE,CN`**，于是落进规则链末尾的 `MATCH`、走节点绕出国再绕回来——实测本机一条供应商每轮 26–41 MB 上下文全都这么走，而本机没有任何信号说这件事（内核日志写的是 `Direct`，那是写在 geosite 载入完成之前的；端点 IP 也确实在中国，错的是**路由**不是目的地）。现在启动 VPN 时读**本机配置的两份供应商表**，把这些 host 同时钉在两处：系统代理的绕过列表（`setproxybypassdomains` 是 macOS 上唯一吃域名的绕过面，默认那串全是地址与网段）与规则链最前面的 `DOMAIN,<host>,DIRECT`（TUN 模式与自带代理设置的客户端走这条）。列表是**拒绝名单**——认不出的 host 一律直连，只有 `anthropic.com` / `openai.com` / `x.ai` / `openrouter.ai` / `googleapis.com` / `nvidia.com` / `lmstudio.ai` 这些**必须走节点**的域名被排除在外；把自定义供应商指向这七家之外的境外端点时它会被当作国内直连，这是这条规则的已知代价，写在 [FAQ](FAQ.md) 里。规则注入的顺序也不能反：必须发生在 `tuneForStability` **之前**，那一步会改规则正文。缩进抄的是 profile 自己第一条规则那一列——机场写列 0、手写缩进两格，假设任一都会让内核直接死于 `Parse config error: yaml`（本机 1195 条规则的订阅实测过）。
- **「流量日志」多了一档「实时连接」，终于有字节数**：明细与汇总回答的是「谁走了哪条出口、命中了哪条规则」——内核的连接行里**没有字节数**、**不记 UDP**，所以那一档回答不了「用了多少」。新增的第三档读内核 `/connections`，每条给出**累计上传 / 下载**与**进程名**（内核识别出来的，不是猜的），并按同一套出口（直连 / 代理 / 拒绝）与同一套搜索筛选。口径写在面板上：它只列**此刻还开着**的连接，短连接可能在两次采样之间就结束了，所以它是快照不是账本。隧道停下时这张表清空，不留上一轮的残影。

### 修复

- **代理日志里已完成的行会当场补上读数**：行缓存按「可搜索字段」的指纹跳过重算，而一次请求**收尾**只就地改写 `endedAt` / `status` / 四个 token 桶——都不在指纹里。于是成功的请求在日志里一直停在待定的灰色 `…`（含右侧的 `…` 桶、待定高亮，以及「复制」复制出的未完成行）。指纹现在覆盖这六个字段，收尾即重算；仍跳过与渲染无关的重复事件。
- **连接器卡片上的按钮终于真的是一枚按钮**：连接器页把 `.buttonStyle(.uiversePress)` 与 `.connectorUtilityButton()` 串在同一个 `Button` 上，而 SwiftUI 只把 `makeBody` 交给**离 Button 最近**的那一个——于是只有「下压 1pt」的样式生效，承载底板、悬停与禁用态的 `ActionPlateButtonStyle` 从未运行，五个操作按钮（启用 / 停用 / 移除 / 定位）一直画成裸字。现在只保留一种样式，由底板自己负责按压与禁用表现。
- **天空整点「跳一下」的接缝没了**：着色器的时间参数此前每 3600 秒取一次余数，而它在这个时钟里唯一的作用是**相位**（云的漂移、雾、雨雪片、水滴生命、抖动都是 `t * 常量`，没有任何一处关心它的大小）。于是渲染满一小时后，整片云、雾、降水与抖动会在**一帧之内**整体重排——实测该帧与相邻秒的平均亮度差约为平时的 10 倍。现在直接传 `t`；Float 在一天的量级上仍有毫秒级分辨率。
- **删掉三个连不上任何画面的视图**：`UsageRelationshipPlot`（163 行的模型来源关系图，调用方在用量分析重组时被删）、`UsageCalendarPlot`（分析面板里的日历块）与 `SourceRingLegend`（环形图旧版图例）都只剩声明——编译进每个构建、渲染不出来。随之删掉只为日历图存在的 viridis 色阶、`UsagePlotPalette.cache/cacheColors/source` 与 `ASSET-LICENSES.md` 里那条色表署名，以及设计文档里对已删图形的引用。
- **删掉一条没有任何读者的「实扣」流水线**：store 上曾有一份 `usageSettlements` 金额表（外加 `settlement(for:)` / `settlementCovers(_:)` / `settlementWindowLabel` 三个访问器，以及每次用量刷新时重建它的 `querySettlement` / `publishSettlement`），但用量页实际读的是 `CursorLedgerStore` 自己——同一事实的两个出处，其中一个谁也没读。现在只剩一个：刷新不再为每个用量 tick 重建一份无人使用的字典。
- **退出时不再把系统代理留在死端口上**：`clearSystemProxy()` 的同步版本从引入起就写着「退出路径保持同步，代理必须在进程消失前清掉」——而实际上没有任何退出路径调用它。开着 VPN 与系统代理时按退出，每个网络服务都继续指向 `127.0.0.1:<mixed-port>`，而那里已经没有内核在监听；同时 TUN 的 DNS 覆盖与它的标记文件也留着。现在 `applicationWillTerminate` 在停内核之后同步清一遍（同时复原 DNS 并删掉标记），代价是退出时多几百毫秒的 `networksetup` 调用。
- **Codex app-server 的崩溃不再拖垮整个应用**：向已经退出的子进程写 stdin 会触发 `SIGPIPE`，默认处置是终止进程——而 app-server 自己退出（崩溃、版本不匹配）本来就是调用方 `catch` 里处理的那种普通失败。写入端从此禁掉 `SIGPIPE`（与 `BatteryChargeController` 对辅助工具管道做的同一件事）。
- **模型页的「导入另一套运行时」回来了**：Claude ↔ Codex 的供应商互导（名称、Key、模型与自动压缩阈值随行，Base URL 各留各的）从 1.9.0 起就在 `ProviderBridge` 里，但发起它的按钮长在已被 `ProviderConnectionEditor` 取代的旧编辑器里，于是这条流水线在 UI 上一直不可达——文档和 FAQ 却一直说「模型页可以导入另一套运行时的配置」。现在页头带里有一个「导入 Codex / 导入 Claude」按钮（随当前客户端切换），结果按连接器页的同一块提示条样式报出（「新增 2 个供应商」「没有可导入的供应商」都算结果）。顺带把错误条也接到同一条提示条上，并加上了关闭按钮。
- **开发图标终于也被无损重压，并有了守护它的测试**：`Tools/recompress-icon.py` 此前只处理正式图标，而文档和测试说明都写着「测试会跑 `--check`」——实际上**没有任何命令调用它**。开发图标因此一直停留在旧编码器的输出上，比同样的像素多 336 KB（它随每个开发包和 zip 一起分发，deflate 帮不上忙，成员本身已经是压缩过的）。现在工具接受图标路径，新增的 `Tests/icon-minimal-regressions.py` 对两个图标都跑 `--check`，并证明把一个副本改坏后 `--check` 会拒绝且不落盘。开发图标 2,220,382 → 1,884,046 B，像素逐成员比对完全一致。
- **VPN 重连后浏览器可能再也上不了网（代理已关，系统仍指向它）**：`networksetup` 只对 **Wi-Fi / Ethernet** 写代理，而 `VpnProxyGuard` 每 10 秒回读一次也只看这两个服务——它回答的是「代理有没有被别的应用清掉」，回答不了「这个应用自己到底把哪些服务写成了代理」。于是重连（改端口 / 换 TUN / 换订阅）时会**在一个已无人监听的端口上留下代理设置**：`stop()` 的那一段只关当前 `preferredServices` 里的服务，而这两处都可能与写入时不同（换了主服务、接了网线），漏掉的那个就一直指着死端口。现在停止与恢复都按**当初写进去的那份服务清单**逐条复原，而不是按「现在哪条是主链路」猜。
- **日志明细不再把往上翻的人拽回底部**：明细列表此前每来一行就滚到最新，于是想回看几行旧记录时，列表每 250 ms 被拽回底部一次。现在跟随是一个**跟着滚动阶段走的状态**（`ScrollGeraHold` 那一套：拖动 / 惯性期间不跟随），滚到离底部 `tailTolerance` 以内才恢复自动跟随，离开底部时右下角出现「回到最新」，点它才回去——滚上去看旧行不再被抢。

## [1.14.0] — 2026-09-29

天气不再依赖代理（改走两家国内源）；Cursor 的实际扣费进用量页；VPN 页新增「流量日志」；问候卡重做成 Metal 大气天空、可切手动时刻与 24 款手写体；设置页按用途重做；概览不再有常驻显示周期。

### 变更

- **天气不再依赖代理**：天气此前只走 Open-Meteo（`api.open-meteo.com` 解析到德国 Hetzner）与 wttr.in，两个域名都命不中 mihomo 规则链结尾的 `GEOIP,CN → Direct`，于是落进 `MATCH` 走代理组——VPN 节点一慢或一挂，概览卡的天气就没了，而关掉 VPN 时那两个接口其实一直是通的。现在取数顺序改成**高德 → 中国天气网（免 key）→ Open-Meteo → wttr.in**：前两家都是国内 IP，命中 `GEOIP,CN → Direct`，开不开 VPN 都走直连，境外源退成海外城市与极端情况的兜底。高德 key 在**设置 → 通用 → 天气与问候 → 高德 Key** 里填（只覆盖大陆城市，留空自动跳过、直接用免 key 的中国天气网），**不写进代码**——城市名到 中国天气网 cityid 的对照表编译在二进制里（该站的 `toy1` 名字搜索接口已经失效、对任何中文城市名都返回空数组，表由 `Tools/gen-cn-weather-cities.py` 从仍在服务的省→市树生成，只到地级市）。两家国内源都不说 WMO 码：高德给中文（"阴"/"雷阵雨"），中国天气网给 `d00`/`n7`/`d301` 这套 0–31 的码，两者都塞进现有 `sky(for:)` 会和 WMO 的 0–99 撞车，所以新增 `skyHint` 直接记下天气族、另有 `sky(forText:)` / `sky(forCNCode:)` 两张表；高德的 `windpower` 是蒲福**级**（"≤3"）而非风速，按级换算成 km/h 再喂给风向盘，不能把级别当速度印在表盘上。代价写在明处：两家都不给降水概率（由天气词估）、日出日落与昼夜（留空 / `nil`），中国天气网只给 4–5 天预报（4 天时预报带按实际天数画，标题不再写死「今天及未来 5 天」）。

- **问候卡重做成一片真的天空**：此前那片天是 `Canvas` 在 SwiftUI 里逐帧画出来的（`SkyPalette` 调色 + 云密度纹理 + 手绘降水与天体），能做到的纵深就是「一层背景」；问候语也是一条静态的排印结果。现在天空是**同一条渲染通道里的 Metal 大气**：一个运行时编译的片元着色器按远近分层叠——天空渐变与地平线散射 → 星 / 月 / 日 → 卷云 → 体积云（fBm 密度场 + 朝太阳做 5 步向光采样，Beer-Lambert 透射加 powder 项，天体在云后时有银边）→ 雾 → 远降水 → 彩虹 / 流星 / 闪电 → **问候语** → 近降水 → 卡片玻璃上的雨滴。问候语刻意处在云层与近景雨丝**之间**：云影从字面掠过、雨丝从字前划过、日落时字的一侧被染成边缘光，字本身就是场景的一部分，不是贴在天气图上的一行字。天空按**太阳高度角**（不是钟点）分八个时段、八种天气调色，两两之间线性插值，所以不同纬度与季节都成立；天气变化时调色、云量、降水、雾、星光走 1.2 s 的 `SkyScene.mix` 平滑淡变。运行时编译 MSL 而不是离线 `.metallib`，是因为构建走裸 `swiftc`、没有离线 Metal 编译器，而运行时编译器随系统；`MTKView` 自己持有指针跟踪区，视差与"擦掉"雨滴不会让 SwiftUI 的视图图失效。
- **天空多了一档「手动」**：天空此前只有「跟随现在」这一种，想看一眼傍晚的晚霞只能等到傍晚。现在时钟下方是**自动 / 手动**切换：手动模式下左下角的日轨**就地换成控制台**——八种天气（晴 / 少云 / 阴 / 小雨 / 大雨 / 雷雨 / 雪 / 雾，夜间自动换月亮版图标）、八个时段（按当天真实的日出日落推算，"日落"就是本地的日落）、以及一条 24 小时时间轴（轨道用所选天气下当天每小时的天空色绘制，刻度标出日出日落，滑块带日 / 月与时刻，5 分钟吸附，←/→ 每次 15 分钟）。直接拖动天空也能改时刻，整点有触感反馈。手动模式的天气与时刻**落在 defaults 里**（`greeting.skyMode` / `greeting.manualMinutes`），拖动中只放 `@State`、落定才写回——一次拖动不会写六十次 defaults。回到自动时时刻先缓动回"现在"，天气由渲染器交叉淡变。
- **问候语可以在 24 款手写体之间切换**：问候语此前钉在系统自带的 `SnellRoundhand-Bold` 上，全应用只有这一种笔迹。现在设置 → 通用 → 天气与问候里一行菜单可选 **24 款**：20 款随包（Borel / Pacifico / 四款 Playwrite / Dancing Script / Yellowtail / Satisfy / Cookie / Damion / Grand Hotel / Lobster / Great Vibes / Sacramento / Parisienne / Playball / Kaushan Script / Oooh Baby / Grape Nuts，都是 SIL OFL 1.1 或 Apache 2.0，各自的许可证随字体文件一起随包，版权与保留字体名见 `ASSET-LICENSES.md`）+ 4 款系统字体（SignPainter / Snell Roundhand / Savoye LET / Zapfino，按 PostScript 名查找，缺失时该卡片置灰）。**默认是 Borel**——在 24 款同屏对比里它是唯一单线、圆头、连笔宽松的，最接近那种"手写"的观感；只有单线字体在填充之外再加一圈圆角描边（`Borel 0.012em × 2`、`Playwrite 0.008em`、`Sacramento 0.01em` 等），均匀加粗而不会填死 a / e / o 的字腔，粗细对比强的字体不描，以免糊掉发丝线。字体画廊默认**折起**，只显示当前这一款的字样；展开后每张卡片用该字体、同一套轮廓与加粗写出**当前这句**问候语，点一下即换，切换后问候卡把新笔迹重写一遍（不是硬切）。字体不装进系统、不单独分发；设置页首次展开时在后台读字体与轮廓再淡入，不在主线程读 24 个字体文件。
- **设置页改按用途分四类**：此前是一整面**按数据类型铺开的瓦片墙**（30 多张卡，界面 / 灵动岛 / 花费 / 本机 / 本地代理 / 代理上游 / 第三方接入 / VPN / 连通性 / 关于…），要找一个开关得先猜它被归进哪一类诊断里。现在顶上是四个**按目的**分的分类——通用 / 灵动岛 / 权限与隐私 / 本地代理——内容区独立滚动、切换分类回到顶部；排版也只有一种语法：`SettingsGroup` 起小组、`SettingsRow` / `SettingsToggleRow` 把标签左对齐、原生控件右对齐，最大宽 800pt 在大窗口里居中，组内细分隔线。**刻意不用**卡片宫格那一套：没有每项一张卡、没有彩色图标井、没有深度环与悬停抬升，开关 / 分段 / 菜单一律用 macOS 原生控件，次要动作用中性色按钮——这一页**主动退出**仪表盘的瓦片语法。
- **设置页删掉了一批重复与开发用的入口**：SQLite / JSON 存储实现开关（沿用用户现有配置，不迁移也不清空数据）、VPN 的重复启停入口（VPN 页仍然负责管理 VPN）、独立的供应商连通性卡与 Cursor 状态卡（模型相关操作在模型页、Cursor 数据开关统一在权限页）、五条原始配置文件入口与设置页自己的退出按钮（应用菜单仍可退出）、没有任何操作的「鉴权：令牌」卡（并入接入说明那一行）、Claude Code / Codex 的只读上游卡（第三方供应商仍可独立选）、以及「设置页每 5 秒扫一遍配置目录与已安装终端」那个任务（终端列表改在页面出现、应用回到前台时刷新）。字体画廊从一大片收成一行菜单，所有字体选项与已选值都还在。**城市与端口改在提交或失焦时生效**（切换分类也会提交草稿），端口写错时显示说明并保留原端口，不再把非数字字符静默剔掉；手动汇率改为真正失焦时才提交。
- **三指拖移不再把整个窗口拖走**：主窗口一直开着 `isMovableByWindowBackground`，于是"按住空白处拖动窗口"在**任何**空白像素上都成立——正文、列表、问候卡那片天空，全都能把窗口拽走。问题在于系统「三指拖移」（这恰好是很多人唯一的拖动方式）把三指按下就当成一次已经开始拖动的动作，视图必须把**原始事件**交给窗口服务器才会起拖，单靠 `mouseDownCanMoveWindow` 不够。现在关掉背景拖动，改由**顶部栏自己 opt-in**：`WindowDragRegion` 只是一个空视图，用 `performWindowDragWithEvent:` 把事件转交出去（这个 SDK 的 Swift overlay 没导入那个方法，走 ObjC selector），标签页与帮助按钮在它前面、各自保留点击，标题与状态文字不参与命中测试，双击按系统偏好缩放或最小化。
- **Cursor 的长轮次不再被误判成"闲置"**：Cursor 在一条长轮次里会**持续写 SQLite checkpoint，却可能很久不导出 JSONL**，而旧的运行判据只看 JSONL 的最后一条 assistant 行有没有跟 `turn_ended`——于是正在跑的长任务被判 idle，灵动岛直接漏报（本机实测钉住过一条：JSONL 停在用户消息 21 分钟，`checkpointAt` 只差 30 秒，`composerData` 里新的工具调用还带着 `shellStatus: running`，而监控报 0 个运行中）。现在运行判据是**两条写时钟取其一**：JSONL 的最后一条 user **或** assistant 行在最后一个 `turn_ended` 之后（user 也算，覆盖"提交了但还没等到第一个回复"那段），或者 `max(unfinishedRunAt, checkpointAt)` 在 10 分钟内。顺带修掉几处同源的漏报：查询不再先截断"最近 80 条"再判运行（运行中的会话不受展示数量限制，先判运行再排序）、当前轮次的**成功与错误**结束标记都收尾（此前只有成功那条清运行态）、**旧**结束标记既不结束新轮次也不发旧答案的完成通知、长任务完成后的新鲜度改用实际活动 / 文件写入时间（按提交时间判会漏通知）、子 Agent 改走父会话 `subagents/` 的实际路径（旧代码按独立主会话路径读，读不到）。残留边界写在注释与 [排查记录](technical/cursor-session-monitor-investigation.md) 里：两种数据源都静默超过 10 分钟时仍无法与真正中断的轮次区分，这是启发式窗口，不是证明。
- **Codex 额度重置的提醒不再迟到最多 15 分钟**：轮询此前是一根**固定的 15 分钟木桶**，重置提醒只能等到下一根桶——重置正好落在轮询后一秒，就得白等一整个周期，平均也要迟 7.5 分钟，而这条提醒的全部意义就是「现在又能用了」。现在 `QuotaPollScheduler` 在**心跳之上多瞄一眼**：15 分钟一次照旧（额度是被消耗的，读数要持续在屏幕上走动，这与重不重置无关），但只要某个窗口的 `resetsAt` 落进未来 15 分钟内，就额外在**那个时刻过后 5 秒**探一次，于是重置通常在几秒内被报告。这一眼落在 `resetsAt + 5s` 而不是那一刻，是因为服务端的重置时间是**取整到分**的，设备时钟也可能偏一两秒，踩在整点上会读到旧值。读到之后照旧要过 `QuotaResetDetector` 那套防误报判定——排程只管**什么时候看**，造不出提醒。若到了那一刻读数没动（Codex 有时先换 period 再更百分比），心跳一直在下面跑，只会晚一次心跳而不会漏。
- **Cursor 的额度进了 popup 与概览**：Cursor 是应用一直在看的第三家客户端，却**只有它没有额度读数**——popup 的切换行把第三格给了 VPN，概览上也没有它的位置。现在新增 `CursorUsageFetcher`：直接读 Cursor 自己存在 `state.vscdb` 里的账号 token（不需要登录、不需要浏览器 cookie），并区分**两套鉴权面**——`api2.cursor.sh` 的 Connect RPC 收**裸 JWT**，`cursor.com/api/*` 的 web 端点收 `<sub>::<jwt>` 百分号编码后的 cookie（且必须带 `Origin`），写反就是 401。读出来的是**两条独立的额度**：月度套餐（`GetCurrentPeriodUsage`，含金额与计费周期）与 Grok Bot 的周窗口（`get-sand-usage-status`），两条各有各的重置，所以分两行显示而不并成一个数。popup 的切换行第三格改成 Cursor 额度 chip（月度 / Grok 两个表盘 + 花费行），**VPN 移回状态行变成一颗药丸**（它是一条连接状态，不是一种模型）；概览问候卡的模型区也多一行 Cursor 读数。轮询 20 分钟一次——两条窗口一个按月一个按周，这个频率看不住任何东西。
- **概览问候卡：预报折进天气 HUD，天气详情 popover 下线**。dock 里那条横贯全宽的「天气展望」是上一版 popover 内容平铺进卡片的结果，它让整张卡很高，而它载的信息（六日走势）**不需要占三分之一的卡**：`ForecastStrip` 把今天 + 未来五天画成**细列**（周几 / 符号 / 低高）放在 HUD 当前温度下面，一眼就能答「这一周怎么走」。随着预报内联，620pt 的 `WeatherDetails` popover 整个删除——它的其余内容（温区条、太阳高度曲线、日出日落）已由 HUD 与内联预报承担。天空带随之从固定 400pt 收到 272 / 300pt（按宽度），dock 从三区收到两区。
- **问候的名字改用拼音**：卡片上其他字都是英文（`Good afternoon`），只有署名一行是汉字，于是它成了唯一一行不匹配的。`MachineIdentity.displayName(for:)` 把汉名按**拼音、名在前**写出——`王夏军` → `Xiajun Wang`（不是 `Wang Xiajun`：其余文字的书写顺序是名在前）。已经是拉丁字母的名字原样保留（`Sam` 还是 `Sam`）。姓氏取**第一个字**而不是查表：双字姓（`欧阳修`）会被读成 `Yangxiu Ou`，这是这条规则唯一拼不对的形状——一张 ~80 个双字姓的表是比这一个名字更大的错误面，所以规则保持简单并写在注释里，而不是半途建表。
- **popup 宽 424 → 460pt**：多出的 36pt 全给切换行——三列各 143pt，`deepseek-v4.1-flash` 这样的长模型名能整名放下（此前 127pt 列把它截成 `deepsee...flash`，最要紧的中段没了），Codex 额度的两个窗口也终于不必缩写。`MenuBarView` 的 `frame(width:)` 与 `MenuBarController.sizeAndPosition` 是两处数字，注释里写明必须相等。
- **问候带的天空可以用键盘漫游**：横向拖动预览前后 12 小时之外，左右方向键各走一小时、Esc 回到现在，四条无障碍动作同名；松手后 0.75 秒缓缓回到当下。作为代价，**未来某天的预报不再改写整片天空**——选一天预报是那张卡自己的读数，不该把整扇窗重画一遍。

- **CC / Codex 的图标全应用统一成同一枚品牌方块**：两家客户端的图形此前是**按调用点各画一次**——popup 的 CC / Codex 切换块、灵动岛的会话徽章、模型页的分段控件、设置页的连通性块、连接器页的平台筛选，一处是真实品牌图、一处是 SF Symbol（`command` / `terminal` / `chevron.left.forwardslash.chevron.right`），于是同一个产品在不同页面有不同长相，而 `terminal` 那种写法说的其实是「一条命令行」，不是这两家客户端。现在统一到 `ProductBrandMark`：**Anthropic 的 `A\`** 与 **OpenAI 的花结**（LobeHub 1.97.1 的真实图形），套在 `Theme.bgSecondary` 的圆角方块里——纯粹的黑标放在深色卡上、白标放在浅色卡上都会**看不见**，所以这层底色是图形的可读性前提，不是装饰。新增 `GlyphWell(brand:)` 让「持有一家客户端」的方块能画品牌图，`ConnectorsView` 的平台筛选与 `SettingsView` 的连通性块改用它；`SegmentedCapsule` 原本就有的 `brand:` 也接回了连接器页。
  - 同时修掉底片本身的尺寸问题：LobeHub 的 PNG 各自带着到画布边缘的留白，实测在 **13pt 的 popup 块里 Anthropic 只剩 65%、OpenAI 更小**，读起来是一团糊。新增 `Tools/gen-brand-marks.py` 把图形剪到自己的墨迹、按画布 90% 写回 `Sources/BrandAssets/`（构建随包内置），于是**两家在同一个方块里同宽**——一格里并排的 CC 与 Codex 才看起来是同一个尺寸。`Tests/product-mark-regressions.py` 用 `ImageRenderer` 渲染 10 个尺寸重新量这条比例，并拦住「退回手画几何」这种改法。
- **修掉「今日用量」里的货币图标**：那颗「¥ 加一道斜杠」原意是「估算」，实际读起来是**划掉 / 失效**——细斜杠压在 11pt 的货币符号上，第一眼就是「这个被禁用了」，而且旁边那个格式化金额自带一个**普通 ¥**，于是同一颗胶囊里并排出现两个 ¥ 形记号，比只留一个更糟。现在改成 `yensign.circle`（干净的圈 ¥，标清币种），把「估算」还给文字：胶囊里多一个 **估** 字——它本来要说的意思，用一个真正的字说，而不是用一个意思是「坏掉」的记号。
- **Codex 额度的刷新入口改成看得见**：上一版用「悬停时重置时刻变色」做可点击提示，这只有在**已经知道**那条 lane 是控件时才成立——「点哪里是刷新 codex 额度？」这个问题本身就说明没人知道。所以 lane 上现在挂着一颗 **↻ 刷新** 小胶囊（悬停展开成「刷新额度」，查询中变成「刷新中…」，颜色用 mark 自己的色）。**整条 lane 仍是点击热区**——胶囊是「这里能点」的标签，不是要你精确命中的小按钮——但「存在一个控件」这件事在**静止态就写在脸上**，不用先悬停。胶囊占自己的一行（15pt），所以它不会压住「5 小时」和轨道。
- **点 Codex 额度即可刷新**：额度段落到 mark 的 lane 之后，卡上就没有再读一次额度的入口了（旧版底部那段自带「刷新额度」按钮）。现在**那条 lane 本身就是刷新控件**——按钮就是你按它去重读的那个东西，所以触点落在读数上而不是旁边的图标上。悬停时 lane 的重置时刻从安静灰**亮成 mark 自己的色**，这就是全部的可点击提示（lane 是一条**读数**，给它套一圈按钮边框它就不再像读数了）；点击中按钮禁用，避免连点叠请求；空 lane 仍写明原因（「正在读取额度…」/「Codex 额度查询失败」）并保留一条空轨道，所以读不到额度时不会既没字也没高度。VoiceOver 得到一个 `isButton` 的「刷新 Codex 额度，5 小时剩余 N%，7 天剩余 M%」，整格的 tooltip 也改写成「点 Codex 额度可刷新，点其余处打开模型管理」。

- **「连接」详情改成三段式检查器，并且不再暗示「能上网」**：
  - 这一版取代了中间那版「一台机器 + 四只环」。环的形状在回答「多少」，而点开连接要回答的是**走哪条路、过哪道门、挂了什么**——三只环各自去量一个位置，等于把三个不同的问题画成了同一只表的三次读数。现在是**网络 / 本机代理 / 附近与设备**三段：网络段给链路本身的状态与一根标定过的 RSSI 尺（刻度是 dBm，不是时间），代理段是这台机器上唯一由本应用拥有的一条连接，设备段是挂在上面的耳机（每台写明电量与过期与否）与隔空投送入口。
  - **卡片和面板从此说同一套词**：`ConnectionStatus` 是唯一的链路词汇表（以太网 + Wi-Fi 同时在线、Wi-Fi 开着但没接入、只有蓝牙、离线，各有各的说法），`ConnectionSignalScale` 是唯一的 RSSI 尺，两处共用，所以同一张卡和它自己的弹出框不可能对同一条链路说两个词、也不可能把 −46 dBm 画成两个长度。卡片的正文换成状态标题 + 信号尺 + 一行副文（有耳机时右侧跟着耳机图标与电量），不再是一排小 mark 加一句状态词。
  - **接入 ≠ 可用**：面板明写「网络接入状态不代表互联网可用性」，本机代理那一段明写「检测本机服务是否响应；不代表上游模型可用」。一个在监听的进程是一条连接，一个已接入的接口是一条链路，两者都不是互联网。
  - 动效只剩本机代理那颗呼吸点（Core Animation 图层，监听中才动）；四只环那套 hover 扭转随之删除。地址行仍然只在底部「复制诊断」里。

- **连接卡片可点，弹出「连接」**（`ConnectionDetailPanel` 重写）：一张卡同时是四个不同的说法（Wi-Fi / 隔空投送 / 以太网 / 耳机），所以"点开看到什么"必须对四者是一个意思。**当时的形态**是四块：① 这条流量走的路（无线电 → 本机 → 蓝牙设备，以太网接入时左侧换成以太网）；② 链路质量（RSSI 刻度 + 弱/强两端标注）；③ 本机代理这一跳（`127.0.0.1:<port>/v1`、是否在监听、以及设置页那颗一模一样的检测按钮 —— 这是整台机器上唯一由本应用拥有的一条连接）；④ 蓝牙设备（每台设备的电量与连接方式）；底部两个出口 `流量明细` 与 `打开网络设置`。**这两版都已作废**：四块之后一度换成四只环 + 复制诊断，现在则是三段式检查器（见上），底部两个出口没有再回来。
- **风扇图形重设计**：概览使用简洁 SF Symbols 矢量风扇，详情使用插画中的涡轮扇叶与按 RPM 连续旋转的动效。点击概览风扇直接切换最大 / 自动，点击卡片其余区域打开详情。
- **本机负载的 mark 换成 Lucide 官方图标 + 独立读数条**：CPU / GPU / 内存 / 硬盘现在分两条 lane —— 上层是 Lucide 自己的 `cpu` / `gpu` / `memory-stick` / `hard-drive` 图标（由 `Tools/gen-lucide-hardware.py` 从上游 SVG 生成到 `Views/Shared/LucideHardwareGeometry.swift`，`Sources/Licenses/Lucide.txt` 随包分发），下层是读数条：**CPU 每个逻辑核心一条、GPU 每组图形子单元一条、内存按页类别、硬盘按已用/空闲，条的高度就是它自己的读数**。CPU 有几核就有几条，所以 12 核可以数出来、6 核忙就是 6 条满格。图标负责「这是哪个部件」，读数条负责「它有多忙」；两条 lane 分开是因为把读数塞进图形里会互相打架（条会穿过 GPU 的接口圆和内存的芯片窗口）。另有一条按读数调速的光扫过读数条：满载约 0.6 秒一次、轻载约 2.9 秒，**低于 4% 完全静止**（和风扇 `rpm >= 80` 同一条纪律），开启减弱动效或窗口不可见时同样停止。图标背后**没有**转圈的弧或环 —— 22–28pt 上的闭合形状读起来是「转圈 = 等待」，机器在干活时没有一个格子是在等待，而且它复述了下方几行已经印出的数字。

- **全应用换成一套表面语言**：卡片、瓦片与筛选控件此前各页各写一套，现在收敛到 `Views/Shared/UiverseSurfaces.swift` 的四个部件——底 + 强调水洗（卡片自己的色相 5–17%）、内嵌 1pt 白环、角上**不同心**的三层深度环（每层同时缩小并朝角落漂移，漂移才是"深度"的来源；一个 `Canvas`，不画字形）、悬停时亮成强调色的描边 + 2pt 抬升。`panelCard()` 与 `.tile()` 是同一套的两种密度，因此概览、会话、用量、供应商、连接器、设置六个宫格里的卡片现在是同一个物件。
- **筛选控件统一为滑动药丸**：连接器的类型筛选与平台行、供应商的客户端切换与分类筛选、用量的周期条、VPN 的分组条，全部换成 `SegmentedCapsule`（一个胶囊井 + 一颗 `matchedGeometryEffect` 滑动药丸）。此前"胶囊里套一串小胶囊"的形状会在一张外卡里再画四张卡，选中态只能靠"谁有填充"来读；现在分组是一个表面、选中是一颗会移动的药丸。
- **卡片带上自己的色相**：会话瓦片按来源（CC 蓝 / Cursor 紫 / Codex 绿）、用量与设置瓦片按自己的信号色、供应商卡片按状态（未配置灰 / 待完善琥珀 / 已配置未激活蓝 / 已激活绿）上水洗。状态此前在供应商页说了三处（水洗、描边、徽章）而只有徽章带色，现在三处一起走同一个状态色。
- **连接器页非卡片态也有形状**：扫描中多一条走带（`DecorativeMotion.kind == .conveyor`，Core Animation，扫描结束即停），扫描/空态与卡片共用同一套表面；「连接器」这一页的卡片另外带一层悬停 3D 倾斜（`.depthTilt()`，只在被悬停的那一张上生效，见 [DESIGN.md](../DESIGN.md) 的 Motion / performance）。
- **额度表盘改为沿弧走的圆点**（`OrbitGauge`）：`CodexQuotaGauges` 由「圆环 + trim」换成 300° 弧轨 + 一个站在当前读数上的圆点。
- **品牌方块补齐到四家：Cursor 与 ClaudeBar 自己**：上一轮统一了 CC / Codex，这一轮把剩下两家也补上，两个都是「画了，但画错了」的同一类问题。
  - **Cursor 不是 `cursorarrow.rays`**。那个字形在会徽章、会话分区头、popup 与设置页上画了很久，它**确实**是一支指针，所以看着合理——但 Cursor 的 mark 是一个**立方体**，而任何 tint 或尺寸都不能把一枚 SF Symbol 变成一家公司的标识。现在它走 LobeHub 的 `cursor.png`，和另外两家同一套归一化、同一个方块。
  - **「第三方」也该有 mark**。用量图例里三项有图形、第四项只有文字，读起来是**一行没画完**，而不是一次刻意的区分（用户就是这么反馈的）。ClaudeBar 自己有一枚 mark（从 `Sources/AppIcon-1024.png` 由 `Tools/make-claudebar-mark.py` 推出），所以四项都带 mark 了。`UsageSourceMark` 现在对**每一个**来源都返回一枚图形，包括第三方——它不是一个客户端，但它是这个应用正在命名的东西，而这个应用有自己的 mark。
  - **修掉一组真的会画出「看不见」的 bug**：`-light` 文件里是**黑墨**、`-dark` 文件里是**白墨**（LobeHub 是按背景命名的，不是按字形），而旧代码在显式传 `page:` 的两条路径上把它读反了——灵动岛在浅色主题下于是画出黑底黑字。判断依据现在是**页面**而不是主题：`page: true` 是黑底（灵动岛在两种主题下都是黑的），`false` 是亮底。同一批还修掉一个小组件的静默降级：扩展有它自己的 `Bundle.main`，构建脚本现在把 `Sources/BrandAssets/` 也复制进 appex，否则小组件的分区头会画成兜底字形，看起来就像一次有意的改动。
  - **归一化从「共享边长」改成「按宽度」**：图形剪到墨迹后按画布 90% 写回，但定标用的边长——Anthropic 比宽高、OpenAI 是方的，这两家都落在 0.90 宽；Cursor 的立方体是 0.88（比宽**高**），于是被画小了 12%，一行里并排明显比邻居小一圈。现在按宽度定标，一张竖高的图形也被允许比 90% 更占竖向空间。
- **所有会变的数字都走灵动岛 token 的逐位滚动（续）**：补齐上一轮漏网的「导入选中 (N)」按钮标题（自绘 `Text`，否则够不到那个 `Text`）等叶子，写法上仍不配隐式 `.animation(value:)`。
- **「继续会话」的终端菜单换成凹槽**：设置 → 界面 → 继续会话原先是系统菜单（Aqua 外观，和同一张卡上的凹槽并排就是两种语言），现在走 `InstrumentMenuLabel`；代理上游的选择器同样。
- **额度读数补上重置时刻并按窗口给格式**：`CodexQuotaWindow.resetCompact` 对 ≤24 小时的窗口写 `HH:mm`、更长的写「明天」/「N天」；紧凑表盘（133pt 格）现在**同时**印百分比和重置时刻，而不是把后者丢掉。
- **额度查询加了 60 秒快照缓存**：第二次打开 popup / 概览重读是瞬时的（走缓存），而**手动**刷新（popup 的 chip、模型页、面板头）会先失效缓存再取，所以「点了刷新」永远是真的重读。只有可信的快照（无 note 或有窗口）才进缓存；重试从 3 次降到 2 次、退避缩短。
- **「连接」卡片重写：读数搬进 mark 位**。这张卡此前把它唯一的读数摊在一条贯穿全宽的 30 格尺上，右半边空着——它是整条资源条上唯一一张「同伴都画 mark 而它什么都没画」的卡。现在读数住进同一块 **176×130 的 mark 位**（`ResourceStrip.markSlot`）：一个填充的信号表压在接口自己的 Lucide 轮廓上（以太网是插座、Wi-Fi 是弧），30 格等宽地铺在 −100…−40 dBm 上。接口本身成了参数（`ConnectInterface`，`ResourceStrip` 传实际在用的那条链路，两边都在线时以太网优先），所以这个 mark 是**对这条连接的读数**，而不是页头那枚 Wi-Fi 字形的第二份拷贝。它同时也从「整条上唯一的素色瓦片」改成和别人一样的表面（自己的水洗 + 悬停边，色相取那枚图标的蓝）。
- **RSSI 尺修掉两处画错**：`ConnectionSignalScale` 移到 `HardwareDetailPanel`（它现在只有这一个读者），30 格**等宽**——旧版按 0.7pt/格递增画成了一道楼梯；空格改为实心灰（发丝线版本基本看不见）；加了 `−100·弱 / −70 / −40·强` 三处刻度标签与一个会动的当前位置点。
- **风扇瓦片的色相改为跟模式走**：静息是蓝，手动覆盖（拉满）时是琥珀，与它的 hero 数字同色——此前风扇格用的是和全条其它格一样的平铺色，而它其实是全条上唯一有「模式」的格子。
- **完成通知的判据换成「这一轮交付了什么」，不再是「忙转闲」**。旧规则是「上一帧忙、这一帧闲，然后 10 秒内看到一个新的最终答复标记」，三处都会误报或漏报：被中断 / 杀掉的一轮同样会由忙转闲（于是靠 10 秒窗口去赌），而 10 秒窗口本身在每次轮询间隔上都会漏掉更短的一轮；更糟的是它的记忆会在两次轮询间隔超过候选窗口时被整个清掉，于是**同一条已经读过的答复会被再播一次**。现在 `ConfirmedCompletionDetector` 问的是三件同时成立的事：该会话的**轮次键变了**、它**自己的文件刚刚写过**（60 s 内）、当前**不是忙**。轮次键三家各取本机的权威字段——Claude 是「轮次+步数计数 + 最终答复 uuid」（计数读自 transcript 尾窗，`ProviderStore.enrich` 里做**单调夹紧**，因为窗口滑动会让计数倒退，倒退就等于把旧键当成新键）、Codex 是 `task_complete.turn_id`、Cursor 是 `turn-<字节偏移>`；同一把键只播一次。于是：启动时不会播报卡里已经躺着的答复（首次见到只做基线）、被中断的一轮静默、短于轮询间隔的一轮**能**报出来（忙的边沿落在两次轮询之间，键和写盘没有）、忙转闲之后才落盘的答复也报得出来。通知文案随之改为「最终答复已就绪」。`Tests/completion-notify-regressions.py` 把四条规则（新键才响 / 同键永不重复 / 不新鲜不响 / 首帧只做基线）逐条钉住。
  - **Codex 的那把键顺带修掉两个真实的漏报**：`task_complete` 还带来 `last_agent_message`，而它比「窗口里看到过助手文本」精确——210 条实测完成记录里，凡真的交付了答案的轮次它都是非空字符串，凡被中断的都带 `error`、都是 null，自动压缩与子代理通知那两类轮次也一律 null（这两类在窗口里只留下一条裸 user 消息、没有助手回复，旧写法只能靠猜，猜出来就是一次假完成）。老格式（没有该字段的 JSONL 与 2026-06 之前的 rollout）仍然退回落文本的判断。另外 rollout 的尾部读取窗口从 48 KB 提到 **512 KB**（并且先多读 48 KB 去对齐记录边界）：本机有一条 rollout 单个 `function_call_output` 就有 11 MB，而 120 KB 的窗口整段落进这条记录里时会**看不到任何生命周期事件**——那会被读成「这个线程还没开始」（`hasOpenTask == nil`），完成收不到、连忙态也要等 90 秒的陈旧回退才解除；实测 85 条根轮次里有 69 条写得比旧的 48 KB 还多，所以窗口是按「一条记录的上限」而不是「常见轮次的大小」来定的。
  - **轮询在看不见的时候从 15 s 收到 8 s**（忙 2.5s / 全空闲 5s 不变）：60 s 的新鲜窗口要在这一档里活下来，而轮询被上一轮扫描挤掉是常事（冷缓存下每个会话一次 96 KB 尾部读），所以挤掉时用**一次性定时器** 1.5 s 后补跑一拍，而不是等下一个 8 s——丢的那些拍恰好就是完成检测要读的那些。窗口不可见时这一档的读者是小组件与菜单栏图标。
- **`Hello <名字>` 的招呼语按时辰与节日选**（见下「问候」）：`GreetingPhrase` 先查节日再落到六个时段（深夜 / 拂晓 / 上午 / 正午 / 下午 / 傍晚 / 夜里）。23:28 说「晚上好」正是这轮要修的语感问题。
- **不止一次「今天」的问候**：卡片的日期行与招呼语由**同一条时间线**驱动（此前是两个各跑各的计时器），`SkyGreeting` 移到日期行下面；Codex 窗口的重置时刻单独占一行（`resetLine`）。
- **内嵌白环**：`Theme.innerFrame` / `innerFrameMuted` 是新 token；`Theme.Ink.*`（文字版信号色）与原信号色（形状版）现在分工写明——字、胶囊、计数用 `Ink`，条、点、弧、环、水洗用原色。供应商卡新增 `.faceColor` 承担后者。
- **下压按钮改按用途说话（`ActionButton`）**：`adaptiveGlassButton()` 退场。旧名字描述的是**长相**（它先后是 Liquid Glass、系统边框按钮、铣削胶囊），对「这个按钮**是干什么的**」没有意见，于是用途只能由调用点用 `prominent:` / `filled:` / `ink:` 加一个恰好等于 `Theme.statusError` 的 tint 拼出来——同一页因此可能有两种按钮语言。现在 `ActionButton` 问页面真正要回答的那个问题：`tone:`（这是什么——默认的 `.sparkle` 深色板、`.neutral`、`.accent`、`.destructive`）+ `emphasis:`（是不是本页的默认动作）。约 40 处调用点迁到 `ActionButton("刷新")` / `ActionButton("清空", tone: .destructive)` / `ActionButton("导入选中 (N)", tone: .accent, emphasis: .primary)` 这样的写法；`InstrumentButtonStyle` 与 `ProviderActionStyle` 保留为**同一块板的转发**（那几个调用点按位置传参），所以两种写法不可能漂移。

- **用量页多一行真账单：Cursor 的实际扣费**。用量页上每个模型的金额一直是**估算**——本机 token 乘刊例价表。它是错的答案对 Cursor 这样的平台：Cursor 自己知道它扣了多少钱，而且它把这件事放在一个未公开的 RPC 上（`DashboardService.GetAggregatedUsageEvents` / `GetFilteredUsageEvents`），用本机 `state.vscdb` 里**已经躺着的那个裸 JWT** 就能调——不新增任何凭据。于是用量页的模型瓦片上，同一个模型现在可以有两行钱：`估算 ¥1,284.60`（token × 刊例价）与 `Cursor 实扣 $34.65`（Cursor 自己的账本，与 `chargedCents` 逐条核对过 9,895 行）。**这两行永不相加、措辞不共享、窗口必须说出来**：它们回答两个问题（「按刊例价这批 token 值多少」vs「Cursor 扣了多少」）、来自两个来源、可能覆盖不同窗口，合成一个数得到的既不是估算也不是账单。金额接口收的是**窗口**而不是「日 / 月 / 年」，切到「年」或「全部」时超出 Cursor 的上限，所以退化为账单周期**并标出它覆盖的日期区间**，不让数字消失——数字消失会被读成「数据坏了」，而不是「口径不同」。这个读数只在窗口变化 / 手动刷新 / 超过 6 h 时才请求一次，用量页**从不等待它**（启动时先把上次落盘的 `cursor-ledger.json` 渲染出来），落地后发通知让用量刷新重发一次、`rescan: false`——磁盘上什么都没变，只有钱变了。三条实测形状写进了注释与 [技术 §15](technical/15-model-cost.md)：**token 字段是字符串**（`as? Int` 会把整份聚合读成 0，渲染出来是「这个月没用」而不是报错）、**错误信封 `{"code":"internal"}` 必须返回 nil**（返回空结果等于宣称 $0.00 的免费月份）、**聚合不含 `grok-bot-*`**（一个账期里聚合 $53.51 vs 流水 $57.72）。**不做历史回填**：12 × 30 天分块实测 306 s 且仍有 1 块失败，任何一块最终失败就整体返回 nil，绝不返回残缺的和。
- **VPN 页新增「流量日志」：内核每条 TCP 连接去了哪、走了哪条规则**。mihomo 的 `log-level: info` 是固定写进 header 的，所以每条新建 TCP 连接内核都会写一行 `[TCP] src --> host:port match 规则 using 出口`（dial 失败走 `level=warning`），而这一直没人读——用户在 VPN 页只能看到「隧道开着」，看不到某条请求到底走了代理还是直连。现在这一行变成域名 / 端口 / 规则 / 出口四列，出口按末段归类为**直连 / 拒绝 / 已代理**，另有一个汇总模式：按命中排序的域名、「常见服务走了直连」的告警（例如本该走代理的境外域名命中了 `GEOIP,CN`），以及一条口径说明——**内核只记 TCP、每行不含字节数**，页面上写明了这一点而不是画一个 `—` 冒充 0。入口是**管道而不是文件**：`spawnProcess` 的 `readabilityHandler` 把同一份字节同时喂给 `CoreLogWriter` 和这个解析器，因为 `core.log` 到 8 MB 会重写成尾部，读文件要自己管偏移、还会拿到过期偏移；流式回调天然没有这个问题，页面也因此是实时的。解析按**字节**缓冲、只在 `\n` 切断（分块边界会落在多字节字符中间，真实日志里就有一条被切成 `官网 tcp.bet]"` 的残行），在管道线程上做，主线程只收 ≤4 Hz 的合并发布；环形 1000 行、只在内存。同时要求行里**既有 `time="` 又有 `level=info`/`warning`**——ClaudeBar 自己的诊断也写进这个文件，只看 `[TCP]` 会把它们当成连接。口径见 [技术 §11](technical/11-vpn.md)。
- **概览不再有常驻的显示周期**：概览上此前挂着两条 `.animation` 调度的 30 Hz / 1 Hz 时间线——资源条的读数扫光与问候时钟。它们本身画得不多，贵的是**调度**：只要时间线活着，`.animation` 就让整个 hosting view 每个显示周期重跑一次 layout（[UI 审计待办](reviews/ui-audit-backlog.md) §11 量过：只留一条画纯色矩形的 30 Hz 时间线，一个 `topBar` 空壳就从 4.0% 涨到 14.7%；把帧率从 30 降到 8 几乎不动，43.2 / 43.5 / 41.5%）。所以修法不是降帧率，而是**把像素挪到没有调度的地方**：扫光改为 `ReadingSweep`——每个忙柱一条 `CAGradientLayer`，按 `0.35 + load × 1.35` 周/秒平移，柱体仍由 `Canvas` 在采样变化时画一次，跨采样用 `timeOffset` 保住相位不跳回起点；时钟改成 `.periodic(by: 1)`，秒点仍每秒亮灭一次。于是**概览上除了「Metal 不可用时的天空回落」再没有 `.animation` 时间线**，而画面一个像素没变。同一轮还收掉了滚动时的两处浪费：`ScrollHoverGate` 在拖动 / 惯性 / 动画阶段丢掉 hover 的 enter/exit（指针扫过宫格时每个瓦片都翻转一次 `hovered`、每次都是一次布局），停下后补发一次 `mouseMoved` 让指针底下那张补上悬停；连接器的卡片网格改成 `LazyVGrid` 直接作为 `ScrollView` 的内容（此前套在普通 `VStack` 里，`ScrollView` 按理想高度问它，懒网格会把全部卡片都排出来），模型目录的分组改成 `LazyVStack`，深滚只需排屏幕上的内容。概览的天空另外在滚动期间**定帧**（`PageScrollActivity`，一个引用而不是环境值——每次滚动开始和结束都会变，经 SwiftUI 传就会在滚动最需要主线程的那一刻重算整页），合成器只平移一张静止图层。见 [技术 §8](technical/08-performance.md) 的两节 2026-09-29 记录。
- **雷暴的闪电重做成它真正的样子**：旧闪电是一段固定的 60 → 80 → 40 ms 三段式亮度曲线加一条中点位移折线，所以每次雷暴看起来是**同一个闪烁**，间隔 8–22 秒随机。现在它按闪电真正的读法分两类、成簇出现：60% 是**云地闪**——主通道由三级尺度的直段折线构成，3–5 条分叉向下外侧逐渐变细变暗，白热核心 + 紫蓝光晕 + 触地辉光，同一通道被 **2–3 次回击**重亮（间隔 40–130 ms，每次约 30 ms 峰值后快衰减），所以通道会明显闪烁但形状不变（真实回击复用同一条电离路径）；40% 是**无通道的云内闪**。只有细通道闪，云层——也就是卡片的大部分——每次闪电只亮一次（首击升起、回击期间保持、随后衰减，中间不回暗）。成簇的节奏也照着雷暴单体来：1/3 概率 1.1–2.5 s 后紧跟一次，否则 2.5–8 s。这条时序受 **WCAG 2.3.1** 约束（任何一秒内闪烁 ≤ 3 次），相邻两次闪电间隔 ≥ 1.1 s，注释与 [设计 §5.4](design/greeting-atmosphere.md) 都写明了这一点。截图（预览工具与 `AtmosphereStill`）取固定闪电，雷暴静帧每次一致——否则每张预览图都不一样，没法比对。
- **窗台上的额度读数与弹窗用同一种读法**：问候卡窗台上的 Cursor 与 Codex 胶囊此前各画各的——Cursor 是一圈按**已用**填充的环加一个百分比，Codex 是一对环加「5 小时窗口」的百分比和倒计时，而弹窗的切换 chip 读的是**剩余**。同一份额度在两处读法不同，会被当成两个数。现在两处都走 `SillGauge`：**剩余**百分比（两条窗口都是要花完的上限，「还剩多少」才是用户要的答案），弧线随剩余量增长，≤ 25% 琥珀、≤ 10% 红色；Cursor 分 **Cursor / Other** 两个池（悬停显示花费与重置），Codex 分 **5 小时 / 7 天**两个窗口（悬停显示各自重置），窄卡片只留第一个。重置时刻的文案改成「1:20 后重置」这种完整句子，且从天空时钟的分钟算起——拖动或渲染的天空才和自己一致。**顺带删掉了窗台上的账户 Credits 余额**：官方账号几乎总是 `0 Credits`，它不是用户会据此行动的读数，却占着一枚胶囊。

### 修复

- **问候叫出的是 IP，还是那台笔记本**：问候卡的名字此前读 `kern.hostname` 再切掉 `MacBook` 后缀。两处都错：
  - `kern.hostname` 是**网络**主机名，同一局域网里的任何东西都能改写它——按地址发租约的路由器会把它设成地址，于是卡片会跟用户打招呼说「你好，192.168.10.102」。用户在系统设置 → 共享 里打的名字不在那个字符串里，也拿不到。现在读 `SCDynamicStoreCopyComputerName`（= `scutil --get ComputerName`），卡片和系统说的是同一个名字；拿不到时回退 `Mac` 而**不是**主机名——一句泛泛的招呼是比一个数字更小的错。
  - 问候是一句**话**（「你好，…」），而人对自己机器的称呼是 `王夏军的MacBook Pro`，不是这个应用从 OS 生成的字符串里切削出来的登录名。现在 `MachineIdentity.person(in:)` 从机器名里取人：`的` / `'s` / `’s` 之前是名字（`王夏军的MacBook Pro` → `王夏军`），无所有格时再按机型标记（`deMacBook` / `sMacBook` / `iMac` …）剥掉连接用的 `s`；不足两个字符的前缀是残留标记不是名字，整串保留。`Tests/greeting-name-regressions.py` 用一张机器名表钉这条规则。
- **问候的昼夜判断用的是 UTC 而不是当地时间**（同上一轮 wttr.in 那条）：招呼语必须跟**设备时区**走，它讲的是这个人的一天；天空的星位才走 UTC。
- **`CodexModelMark` 在浅色主题下画不出 mark**：`AppPreferences.shared.isDark ? nil : false` 在浅色下解析到黑墨文件，等于把图形画没了。现在改为 `well: false` 并让卡片自己的底板决定 `page:`（那张带底板的方块实测 1.24:1，反过来 1.13:1，两边都是「看不见」）。

- **天气的昼夜判断用的是 UTC 而不是当地时间**：wttr.in 的 `observation_time` 是 **UTC**，而日出日落是当地时间，旧代码直接拿 UTC 小时去比，于是日落后的天空可能还画着太阳、日出也可能整整差一个时区。现在改读 `localObsDateTime`，并给 `minutes(_:)` 补上范围校验（小时 0–23、分钟 0–59，12 小时制的 `12 AM/PM` 换算也修了：原来 `hour % 12` 把 12 点算成了 0 点）。
- **问候卡升级为状态单后，`CodexQuotaFetcher` 读得出账户 Credits**：额度快照新增 `creditBalance`——`unlimited` 显示「不限量」，数值保留 API 单位（不假装是某种货币），**缺失的余额就是未知**（`hasCredits: false` 不带 balance 时不显示 0），`nan` / `inf` / 负数 / 带货币符号的字符串一律拒绝。官方账号把 Credits 当余额显示。
- **`CodexConfigWriter.readSelection()` 与 `readCurrent()` 分开**：官方账号跑默认模型时配置里没有 `model` 行，旧 `readCurrent()` 因此返回 nil，界面就把「正在用官方账号」读成了「没有配置」。新增的 `readSelection()` 保留这种选择（`model_provider` 缺省为 `openai` 而不是 `custom`），`readCurrent()` 在它基础上仍要求非空 model，两者语义各自写清。
- **菜单栏的 ↓/↑ 与电池常驻，且用颜色区分速率的来源**：这三种读数此前整段挂在 `VpnManager.isRunning` 上——`tickVpnRate` 只在隧道运行时才把格子摆出来，`refreshMenuBarBattery` 也提前 return。于是没有 VPN 的机器只剩一枚 18pt 的模板环：这条 strip 上唯一不需要 VPN 就能给的读数，恰恰是它拒绝在没有 VPN 时给出的读数。现在三者都常驻（笔记本电脑的菜单栏始终能看到电量和网速），**开关 VPN 改变的是「速率来自谁、画成什么颜色」**：
  - **隧道运行**：mihomo `/traffic` 自己的计数，**绿色**。绿=「这些字节在走隧道」，也是这条 strip 上唯一的颜色，不是装饰。
  - **隧道停止**：`SystemThroughput` 从 `getifaddrs(AF_LINK)` 读各网卡 `if_data` 的字节数，按接口做 `UInt32` 回绕差分再求和，得到这台机器真实的收发速率，画成静息的白色。绿数字配一个没在跑的代理等于声称流量在走代理，白数字配 mihomo 在转发又把这个事实藏了起来。工具提示写明「隧道速率 / 系统速率」。
  - `ifi_ibytes` 是 32 位字段，千兆线路上 35 分钟就回绕一次；先按接口做回绕差分再求和，否则一次回绕会被读成掉 4 GB 并夹到 0。休眠醒来后 `Timer` 不补发，所以间隔超过 5 秒的采样不算速率（那是整段睡眠的平均值）。
  - 宽度不再随隧道变化（速率两侧都在），切换 VPN 不会让 status item 改变长度；关掉 VPN 时也不再清空读数（旧写法每次切换都要空等一轮 8 秒采样）。`Tests/menubar-strip-regressions.py` 钉住「宽度不含隧道状态」与「两侧颜色必须不同、且一边是绿一边是白」，并在源码上钉住电池刷新不得再被 `isRunning` 拦。
- **开启「启动管理」后电量不会自动降到目标**：接电、目标 80%、电量 95% 时，旧策略只会在高于目标时*停充*（`POWER_HOLD`），适配器仍直接供电，所以电量可以长时间停在 95%——而用户点的是「管理」。现在 `BAT_LIMIT`（启动管理）在具备主动放电能力、接电、开盖时会主动断开适配器输入降到目标，到目标后恢复适配器直供、低于目标 2 个百分点再允许充电；降阈值同样是这个行为。不支持主动放电的机型明确退化为「仅限充，无法主动降到目标」，手动「放电」按钮同时禁用。
- **「充电」按钮实际在停充**：UI 把 `.hold` 标成「充电」并把 tooltip 写成「充电到上限后保持」，而 C 策略对所有 ≥20% 的电量直接返回 `POWER_HOLD`——50% 点「充电」，实际是停充，状态随即显示「已暂停充电」，只有低于 20% 才被保底分支放行。现在 `BAT_HOLD` 真的充到目标再按滞回保持（高于目标仍只停充，不主动放电），枚举、文案、策略和 C 测试四处对齐。
- **滑杆会覆盖尚未确认的模式切换**：`apply()` 设了 pending，但滑杆没禁用、`setLimit()` 也不检查 pending，而且发命令时用的是最后确认的旧 `mode`——点「放电」后马上拖动，会依次发出 `set 3 80 1`、`set 1 70 2`，最后回到 limit；点「还原系统」再拖动还能把恢复请求整个盖掉。现在所有操作共享**一条请求通道、最多一条命令在途**：滑杆只更新最新意图，回执到达后才提交最新目标，且不会把旧模式附带进去；「还原系统」可以覆盖在途操作，其后的目标修改只保存、不重新启用管理。
- **快速把上限拖回原值会丢掉最后一次设置**：已确认 80%，先拖到 60% 松手、回执前再拖回 80%，第二次因为 `target == appliedLimit` 被跳过，最终只有 60% 发出，而界面和保存值都是 80%。去重现在比较**最新意图 / 在途请求**而不是旧回执值，界面也分别显示目标值与已生效值。
- **阈值修改没有超时，失联后仍显示可管理**：只有 `apply()` 有 8 秒响应超时，`setLimit()` 既不设 pending 也不等确认，运行期也没有回执新鲜度检查——辅助进程不再回报而仍存活时，旧状态会一直显示，`managesLimit` 仍为 true，界面继续显示「松手即生效」。现在每条写操作都要确认和超时，运行期每 2 秒 heartbeat 并在 8 秒无回报时断开、关闭输入、请求恢复系统管理、清除「已生效」显示；`managesLimit` 同时检查输入是否还在、是否在恢复中、是否休眠。heartbeat timer 改用 common RunLoop 模式，避免菜单跟踪期间默认模式 Timer 被暂停。
- **授权期间改上限，实际执行的是点击时的旧值**：`apply()` 在授权前就把 threshold 捕获成局部 target，而授权期间滑杆仍可拖动（只是不发命令），授权结束后发送的仍是旧值。现在授权结束后读的是最新期望状态，并且**授权期间点「还原系统」会取消这次启用**。
- **自动恢复依赖控制面板出现**：`probe()` 唯一的入口是控制视图的 `onAppear`，而概览是 `LazyVStack`——电池控件没出现时「应用启动即恢复上次管理」不会发生；探测时工具未安装/过期还会把 `resumeStarted` 先置位再退出，用户之后去设置页授权也不再续接恢复。现在启动路径主动探测恢复，不依赖界面出现，探测有 5 秒超时与「重新检测」；授权成功后续接恢复；不再用「已经授权」当「管理已在运行」。
- **指令确认与能源读数来自两条时间线**：辅助进程每 2 秒回报的 percent 控制器不用，能源图另取 `ProcessSampler`（后台可到 6–12 秒甚至暂停），于是下面已显示停充/放电、上面短时间仍显示充电。现在有效回执会触发一次**独立电池采样**（不受资源采样慢档/暂停影响），并区分「指令已确认」与「实测电池状态」；指令与电流方向不一致时先显示等待变化，持续超过 10 秒才提示检查电源状态——物理变化不再伪装成零延迟。
- **成功回报不清除旧错误**：未接电点「放电」收到 `adapter_required` 后自动回到 limit，之后持续收到的无错误状态不会清掉 `lastError`，设置页与控制面板一直显示旧失败；过期 revision 的错误还会在版本过滤前写进 `lastError`。现在成功回执清除已解除的普通错误，旧回执不污染新操作，需要保留的恢复失败告警单独区分。
- **能源图把主动控制解释成错误原因**：holding 固定写成「已充满或优化充电暂停」、onBattery 固定写成「未接电源」、assisting 固定归因「电源只能提供…」——本工具主动限充、主动断开适配器输入都会被读成故障。这三句现在只描述观测到的能量流向。
- **退出清理会把用户的管理偏好写成「还原系统」**：终态回报 `mode=system` 是“辅助进程已退出”的清理状态，`receive` 对无错误状态无条件保存 mode，退出阶段若处理到该回报就会把偏好覆盖成 system。现在终态回报与用户偏好分离（`savedMode`），下次启动仍恢复用户最后选择的模式。
- **钉住的截图画笔终于按对的按钮**：钉住的截图右上角那条小工具条是 关闭 / 复制 / 放大 / 缩小，而 `PinChromeBar.tap` 按 `sender.frame.minX` 去对手写的区间（`..<30` / `30..<55` / `55..<80`）。按钮从 `x = 4` 开始、宽 22pt 排下来，minX 实际是 **4 / 26 / 48 / 70**——那三组区间是给 `midX` 写的。于是用户拿到的映射是关闭→关闭、**复制→关闭**、**放大→复制**、**缩小→放大**：按「复制」把图钉关掉，「缩小」根本够不着。现在按 `tag` 路由（`Action` 改成 `Int` 以支撑 `NSButton.tag`），布局算术从此与这个问题无关。
- **`State.missingCore` 从来没有被赋过值**：内核缺失这条路径最后都走 `fail(.coreMissing)`，而 `fail` 对每个错误都设 `.failed(err.logMessage)`——于是五个读 `.missingCore` 的地方全是死代码，其中还有这个失败唯一可操作的出口 `VPNView.coreMissingHint`（写明该把二进制放到哪个路径，并给一个「打开目录」按钮）。用户能看到的只是一行通用错误。现在 `fail` 把 `.coreMissing` 映射到 `.missingCore`，也就是 [设计 §08](design/08-error-handling.md) 一开始就写下的行为。
- **GPU 温度不再每次采样都扫 SMC**：`HardwareSensors.gpuReading()` 一直带着一个「加速器没报温度就从 SMC 取」的回退，而 Apple Silicon 的 `IOAccelerator` 的 `PerformanceStatistics` 里**没有** `Temperature(C)`（本机 `ioreg -r -c IOAccelerator` 实测），所以这个回退**每一拍都在触发**——六个 SMC 键穿过同一把 `ioLock`，就挨着包温读取（包温自己是被 5 秒闸门挡住的，注释里还写着「这一拍最贵的一次读」）。实测每拍 1.41 ms；现在加速器**自己报的**温度仍每拍读（报得出的 GPU 上它才是更热的那个读数，而且只是一次属性取值），SMC 那六键的那条路改走同一个 5 秒闸门，摊下来 3.07 ms/s，是原来的 1/5。这不是主线程开销（采样器在自己的队列上），是与风扇读取抢锁的浪费。
- **出口 IP 探测补上被裁掉的那三个服务**：`VpnNetProbe.fetchIP` 只遍历 `ipEndpoints.prefix(4)`，于是七家里最后三家永远轮不到——其中就有 `icanhazip.com`（唯一返回纯文本的那家），连带着 `parsePlainIP` 成了没有调用者的死代码。而那三家恰恰是前四家（同属一个机房）一起限流时剩下的选择，等于最需要它们的时候它们不在。现在改成按 **12 秒预算**循环（每次尝试本来就有 6 秒超时，按条数截断在全部失败时会把调用方按住 42 秒）。
- **`ConnectorUtilityButtonStyle` 里那句 `.environment(\.isEnabled, true)`**：读起来像保底，实际是把调用方要的禁用态盖掉。这条链上的两个样式各自都会画禁用态（`ActionPlateButtonStyle` 降到 0.34 透明度，`.uiversePress` 经 `ControlPressModifier` 变暗），所以那句代码只会**抑制**别人要的灰。今天没有调用点依赖它（连接器页唯一的 `.disabled(loading)` 挂在刷新按钮上，那个走 `headerControl()`），而这正是把它删掉的理由：下一个想禁用某个按钮的人会撞上一句静默失效。
- **`cp -R Sources/ProviderIcons` 把维护者说明发给了每个用户**：那份 README 记的是 LobeHub 素材的出处、3:1 墨迹下限、哪五个品牌为何换成单色标——它属于仓库，不属于发布包。现在只拷 `*.png` / `*.ico` 与许可文件。
- **删掉一批没人读的字段与死代码**：`AudioAccessoryMonitor.Accessory.productID`、`ProcessSampler.HostStats.memoryCached` / `memoryFree`（连同 `temperatureColor`）、`MachineIdentity.chip` / `model` / `system` / `summary`、`ProviderCatalogEntry.monogram` / `color`（二十二条目录数据里写着、谁也不画）、`SkyPalette.shadowTint`、`CodexProxyTransform.ToolRegistry.merge` 与 `qualify`、`VpnManager` 的 `refreshNow` 之类；`MachineIdentity` 现在只做一件事，就是读那个机器名。
- **配置写盘与备份都走私有通道**：`CodexConfigWriter` 此前用 `String.write(to:atomically:)` 写 `config.toml`，落盘模式由进程 umask 决定（默认安装下是 0644）——而这个文件里装着活的 `experimental_bearer_token`。现在改走 `PrivateFileWriter.write`（同 `settings.json` / 供应商表 / `proxy-token` 一路），并且加 `PrivateFileWriter.harden(_:)`：`FileManager.copyItem` 会把**源文件**的模式一起复制，所以备份一份旧版留下的 0644 配置，得到的就是一份 0644 的、装着密钥的备份；`CodexConfigWriter.backUpOnce()` 现在拷完立刻收窄到 0600。
- **旧版留下的宽权限白拿一拍自愈**：`ProviderStore.hardenLegacySecretFiles()` 对 `settings.json` 与 `codex-providers.json` 各做一次 stat，模式里有 group / other 位就收窄到 0600（每进程一次）。写入本身也会自己治好——私有写入是「先建 0600 的临时文件再 rename」，rename 带上的是临时文件 inode 的模式，所以一个 0644 的目标在下次写入之后**就是** 0600，不需要额外的修模式步骤（`Tests/core-regressions.py` 现在把这条路径也测了）。
- **popup 头部把「官方账号跑默认模型」读成「未配置」**：`codexStore.activeProvider?.activeModel?.name ?? "未配置"` 只认自定义供应商，而跑官方账号时配置里根本没有 `model` 行——于是头部那一行写着「Codex / 未配置」，用户用的却是好好的官方账号。现在读 `configuredModel`（`readSelection()` 的产物，见上），官方账号显示「官方默认模型」、供应商显示「OpenAI 官方」；自定义供应商的名字按 `configuredProviderID` 去 `providers` 里取，不再靠「当前激活的那家」——那是**路由**状态，和「配置里写着哪家」是两件事。
- **装饰环的圆头尾巴在接缝处点亮一个点**：`DecorativeMotion` 的 `scan` 环用 conic 渐变画，`locations = [0, sweep]` 只声明了两端——而圆头端点（`lineCap: .round`）会跨过 conic 的 0/1 接缝，越过接缝那一侧没有颜色声明，就取到了整段 tint，在环上画出一个**孤立的亮点**。现在渐变改成 `[clear, tint, tint, clear]`（`locations = [0, sweep, 0.5, 0.95]`），接缝两侧都是透明的，尾巴怎么绕都不会挤出这个点。
- **高德的「今天」是拿设备时区算的**：`DomesticWeatherParser.reading` 用 `Calendar(identifier: .gregorian).isDate(_:inSameDayAs:)` 挑当天那一格预报——那是**设备**的日历，而两家国内源报的都是中国大陆、预报格的日期按 Asia/Shanghai 写。于是设备在中国时区的东边（东京、悉尼）时，上海当地最后两小时会读到**明天**的高低温；设备在更靠西的时区（伦敦、纽约）时两种日期不一致，挑出来的是**第一格之前**的那一格——同一张卡上「现在 25°」而「today 高 19°」正是这么来的。现在按读数的时区（`Asia/Shanghai`）挑，与同文件里 `WeatherForecastFetcher` 和 中国天气网 两条路径一致。CI 的 runner 跑在 06:00 UTC（上海当地已是次日），这条正好在那时把它掀了出来。

**「模型」页标题错乱、按钮压边**：这条页头带的右半是「副标题 + 自定义按钮」竖着一列，于是它成了全应用最高的一条带（74pt，别的页 68pt），按钮底边还压进内嵌白环里。副标题现在回到标题下面（`PageTitle` + caption 一列），控件单独在右侧、两边 `alignment: .top`——和概览 / 连接器同一种解剖。按钮同时换成共享的 `headerControl()`，不再用页面自己的圆角样式。
- **「连接器」页标题和别页不一样**：这条带自己画了 `GlyphWell(size: 38)` + 22pt **semibold** 标题，而每个别的页面都是 `PageTitle` 的 34pt 井 + 22pt **bold**——两个页面并排就是两个字重、两个井。现在统一走 `PageTitle`，字形与色相由 `PageIdentity` 决定。
- **「连接器」页头按钮灰得像禁用**：`headerControl()` 的井与描边本来就是控件的全部表面，但按钮没有 `.buttonStyle(.plain)`，系统默认按钮样式又在胶囊井**内部**画了一个灰色圆角矩形，两层灰叠起来就读成「不可点」。改用 `.plain`，禁用态改为显式 `opacity`，只在真禁用时变淡。
- **页头右上角的圆弧去掉**：概览和连接器标题右上角画着一段半圆轨道加一个圆点，读数已经写在标题旁边，圆弧本身没有含义，还会压住构成条和按钮。概览改回和会话、用量一样的纯标题（数字和刷新还在，不再包进卡片）。连接器和模型的页头带不再画角上的深度环，也不再画这条轨道。模型目录的分区计数改贴在标题旁边——窗口很宽、下面只有一张卡时，`1` / `11` 以前被顶到窗口最右边，看起来像飘着的页码。供应商卡片角上的三层环同样拿掉，状态色只留在水洗和徽章上。
- **页头卡片不再抖**：概览 / 连接器 / 供应商三个页面顶部的卡片带有网格卡片的悬停"上浮 2pt"，而 hover 热区跟着卡片一起位移——指针停在卡片下缘那 2pt 里时，卡片上浮把自己从指针下移开（判定为离开）、落回又接住指针（判定为进入），于是每帧反复翻转，看起来就是卡片在抽。修法有两层：`TileSurface` 的命中形状钉在**未上浮**的几何上（`.contentShape` 排在 `.offset` 之前），指针区域不再随位移走；整宽的**页头带**再显式关掉上浮（`PageHeaderCard` 传 `lift: false`），只保留水洗、内嵌白环与悬停描边点亮——一页只有一条带、控件又在下半部，上浮本来也没传达什么。角上的深度环后来也从这条带上拿掉了，见上面「页头右上角的圆弧去掉」。网格里的卡片手感不变。`Tests/inflight-animation-regressions.py` 把这两条源码性质都钉住了。
- **走带在循环点会跳一下**：`conveyor` 的渐变跨了两倍的 `ticks` 宽度而只走一个 tick 的距离（即半组），图案在循环处接不上。改为图层宽度恰为 `ticks` 个 tick、位移恰为一组；`Tests/rendering-regressions.py` 现在对「一次循环走一整组」与「全程盖住条带」各有一条断言（原先只覆盖动效生命周期，看不出这个）。

- **被中断的 Cursor 轮次会让灵动岛一直转**：Cursor 在轮次被中断或崩溃时**不写**收尾的 `turn_ended`，而忙碌判定是「最后一条 assistant 行在 `turn_ended` 之后」——这个条件对一条冻结的 transcript 永远成立，于是一次昨天下午死掉的会话把灵动岛的忙碌徽章、2.5 s 轮询档和 1 Hz 采样档一起钉到今天。现在忙碌要**同时**满足 transcript 的**写时钟**在 10 分钟内（`turnLiveWindowMs`）。这条界必须钉在文件的写入时间而不是 head 的 `lastUpdatedAt`——后者在**用户提交**时打一次、轮次进行中不再改（实测 `ckpt − lastUpdatedAt` 有 373 s / 587 s / 1096 s），钉在它上面等于「只显示短于窗口的轮次」，按本机历史会藏掉最近 25 个 composer 里的 7 个。子 Agent 同样上这条界（它连 `recentlyTouched` 那道门都没有）。新增 `Tests/cursor-turn-regressions.py` 钉住两侧：十分钟不写的轮次不再算忙，而**安静了 8 分钟**的真轮次仍然算忙。
- **启动时 Cursor / Codex 额度必然第一次查询失败**：两个探针走**系统代理**，而 ClaudeBar 启动后要等 mihomo 就绪（约 2–4 s）才写入系统代理，启动瞬间发出的查询因此打到上一个会话残留的、已无人监听的端口。旧的重试退避是 600 ms，正好落在代理写入之前，于是那次查询注定失败、读数要等到 15 / 20 分钟后的轮询才出现。现在退避读作 **4 s**（跨过代理写入窗口），Cursor 的读数另外**落盘**（`cursor-allowance.json`），下次启动先渲染上一次的读数再原地替换——屏幕上不会再出现「只有转圈看不到额度」；转圈只留给**从来没有读过**的情况。

### 体积

- **mihomo 内核改为随包内置 `.xz` 压缩档，首次启动在应用内解压**。原始二进制 54 MB，而 deflate **压不动它**（Go 自己的符号表已经很密，GitHub 的 release `.zip` 里仍占 20 MB），所以「下载体积」这一栏一直是它一个人说了算——67 MB 的 app 里，`.zip` 有 20.5 MB 是它。换成 `.xz` 后同一个二进制是 13.1 MB，app `.zip` 从 **29.2 MB 降到 22.1 MB**（−24%），DMG 同理。
  - 解压走 `Utils/XZArchive.swift`：`libcompression` 的 `COMPRESSION_LZMA`，**无第三方依赖**，流式写盘（峰值内存是 16 MB 的 LZMA 字典 + 两个 1 MB 缓冲，不是那 54 MB），实测整档 **0.6 s**。注意它收的是 **`.xz` 容器**而不是裸 LZMA 流——裸流 / `FORMAT_LZMA1` 在第一个 block header 就被拒。
  - 压缩档**提交进仓库**（`Sources/ClaudeBar/Resources/mihomo-core.xz` + `.version`），发布构建直接复用：`package` 里省掉 117 s 的 LZMA，只剩一次 `cp`。版本不匹配时自动重打，打出来的一定是当前 vendored 的内核。没有 `xz` 的机器退化为内置原始二进制（54 MB），功能不受影响。
  - 解压是**解到旁边的临时文件再原子换入**，失败不会在可执行路径上留下半截文件；完成标记存的是**压缩档**的大小，所以内核没变就不会每次启动重解一遍。首次启动实测：启动 → 解压 → `内核就绪：version=v1.19.31`，解出来的文件与 vendored 二进制**逐字节相同**。
- **`AppIcon.icns` 无损重压：2,071,438 → 1,705,955 B**（−365 KB）。这是个 `.icns` 容器，里面每个尺寸各是一张独立 PNG，而写它的编码器把三分之一的字节留在了桌上——单是 1024 那张就是 1,177,354 B，而同样的像素只要 956,743。新增 `Tools/recompress-icon.py` 重编每一个成员，并且**逐像素比对**后才落盘，所以不存在「用一个字节换一个像素」的可能；同一处理也应用到 `Sources/AppIcon-1024.png`（1,177,354 → 956,743）。
- **品牌方块改按最优参数写回**：两个生成脚本此前用的是 Pillow 的默认 `compress_level`；加上 `optimize=True, compress_level=9` 后八张 `Sources/BrandAssets/*.png` 从 615 KB 降到 560 KB，像素不变，`--check` 仍绿。
- **量过但**没有采纳**的两条，记在这里免得再算一遍：**缩到 128px**（内核 640² 原图 90 KB→31 KB；但图标在 38pt 的方块里渲染，实测有 78.2% 的面积存在可见误差，最坏像素差 255，换约 60 KB 不值得）；**插画降到 1280 宽**（只在 5K 屏上才有 1.4% 的像素差，省 40% 字节，但那 40% 是 550 KB，而且这块图已经是页面上唯一一处按原分辨率解码的位图）。

- **退出 App 不再留下孤儿 mihomo 内核与系统代理**：退出时停止内核、卸下速率 accessory、停截图热键。
- **多处尾部读取静默返回 0**：读 transcript / rollout 尾部时严格 UTF-8 解码遇到多字节字符被截断会让整个窗口读不出来（实测 600 份 transcript 中 31 份、291 份 rollout 中 14 份上下文一直显示 0），改为宽容解码；JSONL 存储与原始 SSE 报文同理。
- **含图片的一轮反复 400**：base64 被截断或 PNG 缺 `IEND` 的图片仍被转发，上游每轮都 400 并重放；现在替换为 `[image omitted — incomplete data URI]`。
- **VPN 端口冲突**：不再出现「同一端口跑着第二个内核、系统代理与 TUN 标记还在、流量走未受管的进程」的状态；内核自身报的 `address already in use` 会显示出来。
- **代理健康检查误报**：探测改为携带令牌请求 `/health`，代理正常时不再判为不可用。
- **代理日志与抓包泄漏**：抓包 DB 显式级联删除 payload 行、清扫孤儿媒体目录、限制实时预览缓冲；空闲页超阈值时 `VACUUM`（实测 `proxy-capture.db` 84 MB / 20,581 空闲页 / 2 行有效数据）。
- **余额显示**：不再重复打印 `¥`（DeepSeek 返回 `¥12.34 CNY` 曾显示成 `¥¥12.34`）；非 CNY 显示 `12.34 USD`；URL 的查询串或路径里含 `127.0.0.1` 不再被误判成本地代理。

- **VPN 日志膨胀**：`core.log` / `vpn.log` 限 8 MB 轮转（此前无上限，实测涨到 86 MB）。

- **会话卡悬停操作条对键盘与 VoiceOver 可达**（此前鼠标悬停才可点）；补齐大量 `accessibilityLabel`。
- **主窗口反复关闭 / 打开不再泄漏窗口观察者**（长时间使用不再越来越卡）。
- **删除供应商、清空抓包**均加带名字 / 条数的二次确认。
- **编辑器的校验更严**：Base URL 必须是带非空 host 的 `http` / `https`（此前只看能否解析出 host）；模型名两端空白会被清掉、空名与重名（不区分大小写）都会拦下；保存失败会在编辑器顶部显示可关闭的错误条并**回滚内存里的改动**，而不是静默不动还闪「已保存」。
- **写配置的语义**：空值不再沿用旧值——切到没填 token 的供应商会**清掉上一个 token**（此前会保留，必须手改 `settings.json` 才能删）；`env` 里用户自填的非字符串键（数字、布尔）保持原类型不被改写成字符串；`settings.json` 顶层或 `env` 不是对象时**不再覆盖原文件**，而是报错保留；备份 `.bak` 写失败会在下次写入重试。风扇命令的子进程输出改走 `/dev/null`（此前挂 Pipe 不读会卡住等待）。
- **设置页与模型页的加载**改为懒加载栈，长页滚动手感更稳。

### 性能

- 用量索引重扫不再对每个文件单独 `attributesOfItem`（每个文件少两次 `getxattr`），改为一次目录枚举取回属性。
- 供应商余额、Codex 激活改为可取消的串行任务，连点不再互相覆盖；会话 / Cursor / 外部三类扫描各自加了「已在跑就跳过」的闸门，慢盘上不再叠加重扫。

- 耳机状态改由 CoreAudio 路由变更通知驱动（此前靠定时轮询日志文件），连接 / 断开响应更快也不白耗采样。
- Codex rollout 解析结果按 mtime + size 缓存，未被追加的文件只做一次元数据检查，不再每 2.5s 重读 32 KB 头 + 48 KB 尾。
- 界面动效尊重「减弱动态效果」：页面切换与栈切换在开启该选项时直接跳变，不做过渡。

### 测试

- 新增 `Tests/ui-regressions.py`：从源码切片 + 生成 Swift 编译运行，覆盖心跳发布语义（无变化不发布 / 多次变化只发布一次 / 上限 24 / 缺席会话被裁剪）与 `EqualRowGrid` 布局缓存（内容变化使缓存失效、宽度跟随、回缩恢复）。只需 Python 3 标准库与 `swiftc`，不需启动 App 或任何 TCC 授权。
- 新增 `Tests/core-regressions.py`：覆盖数值边界（`Infinity` / `NaN` / `Int64` 越界不崩）、配置写入的私有原子落盘与 0600 权限、写配置时保留用户自有键（`permissions`、`GITHUB_PERSONAL_ACCESS_TOKEN` 等）并清掉受管键、损坏的 `settings.json` 不被覆盖、备份内容等于改写前的原文，以及 Codex rollout 头尾解析（含 subagent 判定与 `task_complete`）。
- 两者都由 `make test` 与 CI 的 **Regression tests** 步骤执行。
