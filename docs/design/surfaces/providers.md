# 供应商管理

Mode: Operate. 原生 macOS SwiftUI。供应商目录优先，保留冰色／石墨底色与系统圆体。

模型页提供「供应商 / 自动网关」两个工作区。Auto 网关继承现有冰色／石墨表面、系统圆体、原生菜单和控件。用户选择 C 路由拓扑：紧凑网关控制、请求 → 难度 → 模型关系图、选中模型检查器，以及模型池／发现／最近路由工作区。设置和接入示例在独立浮层，已有供应商提交和编辑在独立弹窗。

## Auto 模型池

关系图每页五个模型，优先显示实际请求中的模型与最近两次完成尝试，最多九个节点；节点按池内顺序排列，三个档位的位置固定。紧凑宽度改为上方入口与档位、下方模型。拓扑节点和列表中的长名称单行截断，检查器中的名称和 ID 最多两行；完整内容通过提示可读，模型 ID 可在检查器菜单复制。模型检查器提供低／中／高档位多选；供应商、能力、冷却与凭据状态均有文字，色彩不暗示能力评分。能力未支持以文字／图标删除线、提示与辅助功能语义表达，不淡化信息；能力标记与发现卡的模型 ID／上下文说明使用现有主文字色的 72%，保留凹槽底色上的可读对比。

蓝色流动来自真实连接、响应头与有效输出事件，绿色／红色脉冲表达成功／失败；开始输出后流向返回方向。无请求无动效，窗口遮挡、视图离开屏幕或减少动态效果时停止。关系线端点以 6pt 连接端口标记，节点悬停／按压只改变轮廓与色调，不挪动端口。原生 Core Animation 接管流动，SwiftUI 不逐帧重绘；状态订阅随页面生命周期取消，输出推送每请求最多八次／秒。列表懒加载且按实际数据比较更新。

模型页标题和「供应商／自动网关」切换合并为一个横向标题条；供应商的导入与自定义动作只在供应商工作区显示。客户端／分类／搜索与当前连接共用一个工具面板，减少重复标题卡片。

并发与队列沿用原生设置组：全局并发、默认供应商并发、全局／每供应商等待容量和最长等待可编辑；下方只列池内供应商的实时处理／排队数量及单独并发覆盖。网关数值行采用固定 148pt 操作列、68pt 数字与单位列和 24pt 恢复默认槽；说明位于完整行宽下方，不影响数值或步进按钮位置。原生步进器保留键盘与辅助功能语义。等待仅显示数量，不点亮上游连线。

模型详情和列表提供显式测试入口，可取消；未测试并非不可用，基础文本请求成功后更新健康状态。测试不验证未实际发送的工具／图片／JSON 能力。导入错误先显示具体原因与原供应商编辑入口，不可导入项禁止选择。发现目录的连接选择通过共享凹槽按钮打开搜索浮层，标记当前连接并支持添加；无匹配结果给出恢复提示。路由策略与窄窗口分类也使用共享凹槽按钮和原生选择浮层，避免系统菜单覆盖自定义标签样式。

加入模型是主要动作。接入区默认 Auto 示例不带难度；最近路由展示实际判断来源和尝试结果，不展示提示词或虚构性能。发现仍默认定期扫描、手动加入，能力和价格规则详见 [Auto 网关](../../LLM_GATEWAY.md)。

## 供应商目录

已配置预设、自定义及当前激活卡片的 22pt 状态槽右侧提供「加入 Auto 池」，保持 216pt 卡高和下方激活／配置操作的位置。预设卡片的协议移至状态提示，自定义卡片的模型数量并入说明。未配置卡片禁用导入；官方登录卡片不伪造 API 凭据。导入弹窗按真实供应商 UUID 解析当前模型，支持多配置批量选择、上下文核对；搜索／全选区和底部提交区固定，22pt 选择框与整行色调共同标记选择，已入池项以绿色文字图标标记。上下文输入右对齐且有焦点轮廓；OpenRouter 目录值只读。底部固定免费确认、档位／能力浮层入口与提交，关闭不写入，成功保存才关闭；保存期间禁止关闭或重复提交。手动添加模型复用同样的档位标签、确认和提交结构，600×680 弹窗中表单滚动、提交区固定。关闭和提交保留 Esc／Return 原生快捷键。

发现目录改为最小 250pt、最大 380pt 的自适应网格；卡片无投影，12pt 内边距，名称和 ID 单行，分隔线下将上下文数字与说明分层，配合能力和加入动作；悬停从凹槽变为卡片表面。长文本保留完整提示及可选 ID，已加入显示文字状态，其余操作按真实可编辑状态禁用。搜索使用带清空、焦点状态的共享组件。池内列表把供应商与上下文分开，K 以十进制展示，完整 token 数保留提示；主要按钮在深色表面使用深色文字，保持浅色填充上的对比。

页面标题为「模型」；Claude Code / Codex 切换、分类、搜索同排，标题右侧在供应商工作区显示导入对端配置与「自定义」新增入口；窄窗口将分类收为共享 `InstrumentChoiceControl` 原生选择浮层。下方紧凑状态行展示当前连接、已保存配置数量与「仅显示已配置」开关。目录按模型平台、Coding / Token Plan、聚合与自建分组；激活中的卡片从所在分组移到目录顶部的「当前激活」区，未匹配的接口留在「自定义供应商」区。图标离线打包。

所有卡片统一 216pt，区域为厂商信息、模型选择、状态协议、操作。灰色未配置、琥珀色待完善、蓝色已配置未激活、绿色已激活；搭配文字图标，不只依赖颜色。状态由保存的配置决定，待选模型不会改变状态。悬停改变表面色调、轮廓与阴影，并把卡片抬高 2pt（`offset`，不占用布局空间），关闭减少动态效果时取消位移；卡内按钮按压有弹簧反馈与轻微缩放。

抓包控制使用 30pt `ActionIcon`，以捕获角框与双向数据流组成自有 `capture.requests` 图形。绿色实心状态点表示开启，灰色空心点表示关闭，配合图形色调和细边区分状态。悬停提示说明该供应商的请求报文写入「流量」页，并保留供应商名称与“开启／关闭”的辅助功能值。状态直接读取已保存供应商的 `captureEnabled`，与编辑弹窗和 CLI 共用来源，待选模型或本地按钮状态不替代它。

## 配置：聚焦弹窗

点击已有供应商的配置按钮直接打开单供应商编辑弹窗（640×680），不显示页面右侧详情，也不显示弹窗内的供应商导航栏。复用原编辑模型，保留 Key、地址、协议、高级模型设置与拉取模型等能力。保存才提交表单修改，编辑当前激活供应商时沿用原同步更新逻辑。关闭按钮明确说明未保存修改不提交。多供应商管理就是目录页本身，不再有第二层入口。

新预设使用“连接凭据 → 模型 → 保存”弹窗，不自动激活。普通文本 Key 输入失焦遮蔽，不使用系统 Passwords 控件。

## 激活：先选目标，再提交切换

卡片中间整块区域显示目标模型与所属配置，标为“当前使用”或“待激活”。点击打开搜索浮层：按配置分组、显示完整模型 ID、标记实际使用中的模型以及待选项，支持搜索、上下键和回车。不可用配置显示待完善并禁止选择，空搜索结果给出提示。

选择模型只更新卡片的临时目标并关闭浮层；点击独立激活按钮才调用原有切换流程。默认目标为当前配置的活动模型或首个可用配置的默认模型。即使供应商已激活，选择另一个模型后仍可激活。只有供应商和模型都与当前一致时显示“已激活”并禁用重复操作。模型被删除时不保留悬空 ID，重新从现有配置解析目标。激活失败由现有错误区域显示，未成功写入时不提前标绿。

“官方”是模型平台第一张内置卡片，激活复用还原逻辑；保留已保存供应商，不伪造 Key 或官方模型 ID。模型选择由官方客户端管理。其默认状态表达没有选中的第三方配置，不验证官方登录。

## 交互依据与取舍

- [CC Switch 切换说明](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/2-providers/2.2-switch.md)：明确启用动作，写入后更新当前状态。

本实现将“选择待激活目标”和“写入客户端配置”明确分开，这属于本项目的交互取舍，并非照搬参考项目行为。
