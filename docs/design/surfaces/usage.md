# 用量分析

Mode: Operate。原生 macOS SwiftUI，分析已有本地记录；以明确的读数层级、整齐的共同比例尺度和可检查的真实数据为目标。

## 信息与空间

周期工具栏将前后切换、日期、周期选择和刷新放在同一行；自定义日期选择器按需出现。其后五项读数为本地 Token、有记录的天数、日用量中位数、日用量 P95、缓存命中率。每项采用语义图标、25pt 半粗体圆角等宽数字和说明文字；本地 Token 附真实周期小柱图，活跃天数和缓存命中附比例轨道，P50/P95 以零到日峰值的轴线与位置点呈现。单个周期只画单柱，不补造趋势。宽窗口横向均分，放不下时以两列排列；口径解释通过原生帮助文字提供。

分析区域横向并排两张卡片，放不下最小 380pt 列宽时改为纵向排列。卡片随内容确定高度，取消固定 240pt 高度与底部弹性占位；采用页面现有表面、16pt 内边距、圆角与 SF Rounded 标题。左卡是「用量热力图」（`activityCard`）：按周期换形态（日 → 当周 7 大格，月 / 年 / 全部 → 贡献网格），标题栏右侧写明有记录的天数，图下方是「少 → 多」色阶图例与四个来源的品牌读数行（各自份额）。右卡是「Token 构成」（`structureCard`），12pt 分段条，下方两列四块紧凑明细展示 Token 类型、数值与份额，缓存命中率收进标题栏。两张概览图共享浅深主题的靛蓝、青绿主色及少量琥珀、紫色辅助色；分段采用实色，不用渐变，零值保留明细并使用弱化颜色，图形长度仍严格对应实际比例。

多周期用热力图（`UsageHeatmap`：日 60pt / 月 132pt / 年 108pt，紧凑档 28/56/56pt）加五项读数展示，支持悬停查看与按月 / 日下钻；分析卡片不加装饰动画。

## 数据口径

| 项目 | 当前实现 |
| --- | --- |
| 本地总量 | 模型记录中输入、缓存读取、缓存写入、输出之和，不包含 Cursor 官方账单 |
| 时间记录 | `DayUsage` 按日期合并；已到达且无记录的日期记零，未来日期排除 |
| 日／月／自定义 | 按日观测；单日没有小时采样 |
| 年／全部 | 按月汇总；全部周期超过 730 个已到达日期时按年汇总 |
| 全部起点 | 第一条本地日期记录；没有日期记录时从今天开始 |
| 日 P50／P95 | 包含零记录日，排序位置 `p × (n − 1)`，相邻值线性插值；显示转为整数 Token |
| 桶中位数 | 当前显示粒度的桶中位数，不等同于始终按日计算的指标 P50；分析模型保留该值，主图不绘制中位线 |
| 缓存命中率 | 缓存读取 ÷（输入 + 缓存读取 + 缓存写入）；分母为零显示破折号，输出不入分母 |
| 桶 P25／P75 | 当前显示粒度的桶分位数，包含零桶，与日 P50／P95 使用同一线性插值算法 |
| 周期分布 | 真实观测保留重复值及零桶；样本不足时按每个实际数值汇总精确频数，不划分直方图区间 |
| 核密度估计 | 至少 5 个桶且至少 3 个不同数值时计算高斯 KDE，采用 Silverman 带宽与零边界反射；密度形状明确标为样本估计 |
| ECDF（保留数据） | 当前粒度每个桶作为一次观测；`F(t) = count(Token ≤ t) / 桶数`，合并相同值的阶跃，保留零桶；界面不再显示 |
| 模型份额 | 分析模型的本地 Token 份额以全部正值模型为分母；下方模型卡片显示完整清单，不设 Top N 限制 |
| 模型来源关系 | 连接量为对应模型与来源的实际 Token；图形连接量与模型汇总总量保持各自数据范围 |
| Lorenz | 全部正值模型按 Token 升序，横轴累计模型比例，纵轴累计 Token 比例，从原点到 100% |
| 有效模型数 | `1 / Σp²`，p 为全部正值模型的 Token 份额；无模型为 0，等权时等于模型数 |

时间记录、模型汇总和来源汇总保持各自实际数据范围。成本估算和 `Cursor 实扣` 分别标注，不相加，不从本地 Token 推测缺失账单或节省金额。

## 两张分析卡片

多周期以真实观测日构成的热力图（`UsageHeatmap`，颜色为 `Theme.chartPurple` 的透明度梯度）展示，悬停查看读数的同时可点击下钻；单周期用横向份额条和品牌读数展示来源比例，不构造小时趋势。来源总量保持自身记录口径，不包含 Cursor 官方账单。

Token 构成的分母是全部本地模型记录，提示侧为输入、缓存读取与缓存写入之和，缓存命中率不含输出。零数据保留标签和数值，以中性空轨道呈现。`UsageAnalysis` 仍计算日历、分布与 Lorenz 点列，但当前概览不绘制它们。

## 记录明细

「按平台」展示 Claude Code、Cursor、Codex；有第三方代理记录时增加第四张来源卡片。平台归属由调用客户端决定，Codex 包含官方、自定义模型及归档会话，不按模型厂商筛选。本地占比以三类本地来源的总量为分母，与上方概览一致；Cursor 官方账单因区间可能不同保持独立，不合并计算平台占比。

平台、供应商卡片固定 260pt 高；模型卡片最小列宽 320pt，按内容确定高度，不设置占位最小高度；使用惰性网格，仅模型区域调整列宽。卡片直接展示明细，不再通过点击卡片展开；平台和供应商的较长明细在卡片内部滚动。移除平台和供应商装饰曲线，关闭卡片抬升与文件夹预览交互。Cursor 与其他平台共享标题字体、缓存命中徽标、主数值、分隔线、模型列表、Token 构成条和表面，保留真实账单日期、周期覆盖不足和刷新失败提示。

「按模型」取所选周期的本地记录与 Cursor 官方窗口记录的完整集合。名称只去掉既有规范定义的路由前缀、日期和 effort 后缀，同一模型合并本地别名后保留来源分量和估算金额；Cursor-only 模型也有卡片，零 Token 但存在官方记录的模型仍保留。每张卡片明确区分本地 Token、Cursor Token 和账单日期，两种窗口的数量不相加。标题独占一行（最多两行），调用次数和缓存徽标放在下一行；主 Token 与金额分行。64pt 来源环旁的图例把名称／百分比与数量分为两行，百分比和金额保持完整。来源环反映主读数对应的记录，Token 构成条来自真实分量，替换模型卡片的装饰曲线。模型卡片移除扫描、数字滚动、悬停监听和角部装饰透镜，并禁止继承外层动画。金额标注本地估算／本地未计价与 Cursor 实扣，真实零扣费显示 `$0.00`。

「按供应商」优先使用 Codex 会话 `session_meta.payload.model_provider` 的明确标识：`openai` 和应用的 `openai_http` 归入「OpenAI 官方」。查询按所选区间读取 SQLite/JSON 的文件级汇总，在后台读取对应会话头部，不读取凭据或改写索引。该部分从 Codex 模型总量扣除，避免重复计数；其余用量按对应客户端当前配置匹配，缺失或多重匹配留在未归属。仅凭 GPT 模型名不判定为官方；Cursor 官方账单保持独立。


## 状态与性能

首次进入且尚无已完成统计时显示读取状态。切换日、月、年或翻页时保留上一份完整概览，仅在已发布区间与选择一致后接收新数据；分析视图保持稳定身份，异步计算完成后将数字、图表输入与来源读数一起更新。数字使用滚动过渡，构成条按四种归一化份额插值，热力图形态和等高卡片的高度平滑变化，不淡出整页；开启系统减少动态效果时取消这些过渡。加载指示器保留固定工具栏位置。输入变化时以独立任务计算 `UsageAnalysis`（含经验分布、核密度与 Lorenz 点列，当前概览不绘制）与来源总量；取消后的结果不发布。`UsageHeatmap` 每帧只构建一次 `byDay` 与峰值，悬停仅检查已算好的结果，不重聚合记录。切换数据后清空日期检查选择。模型清单单次聚合中缓存每个原始名称的规范化结果，减少本地、来源、Cursor 列表重复执行正则；每张模型卡片的本地／Cursor 金额分别只转换一次，供文字和辅助功能复用。这些是源码层面的开销削减，未做运行时性能测量。

## 研究来源、署名与验证

本轮图表研究参考 [Apple Charts HIG](https://developer.apple.com/design/human-interface-guidelines/charts) 与 WWDC22 [Design an effective chart](https://developer.apple.com/videos/play/wwdc2022/110340/)，采用明确摘要、可检查数量、受控轴密度和辅助功能读数。[Anthropic 官方品牌指南](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md) 的珊瑚色 `#D97757` 与柔和蓝 `#6A9BCC` 提供分类配色方向，原生界面仍使用 SF 字体与现有 Theme，浅深主题分别定义图形颜色。

[Nature 图形规范](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/) 提供清晰轴线与刻度、可读标签、颜色图例及减少重叠和多余装饰的参考。[Observable Plot Dot](https://observablehq.com/plot/marks/dot) 展示以面积编码数量的圆点语法，其半径通道默认使用平方根尺度；[D3 Arc](https://d3js.org/d3-shape/arc) 说明以起止角度、内外半径构造环形分段。本实现借鉴这些数据表达方法，并按原生应用的可读性与交互调整，不宣称已符合期刊发表或导出规范。

实现依据为 `Sources/ClaudeBar/Utils/UsageAnalysis.swift`、`Sources/ClaudeBar/Views/Shared/UsageAnalytics.swift`、`Sources/ClaudeBar/Views/Pages/UsageView.swift`。本文记录当前源码的布局和数据口径；数量来自记录，不补造小时趋势、缺失日期记录、账单或节省金额。用量页没有离线预览脚本（生成 `.build/usage-chart-preview` 的那一个已随旧版图表删除），`Tools/render-mainwindow-preview.py` 的整页合成会带上这一页；预览只覆盖所渲染的记录与窗口尺寸，不执行应用生命周期、原生菜单或悬停交互，不能视为实际运行验证。未启动应用或执行 VPN、系统代理、DNS、TUN、硬件及其他系统集成验证。
