# 模型池可视化验收

布局方向等待用户确认。三份概念图是示例数据，不能作为真实请求、模型健康或能力证据。

## 布局

- 主窗口最低为 900×600；从真实侧栏和页面内边距计算剩余宽度，不拿概念图宽度当作最小宽度。
- 模型名称、供应商和 ID 使用长文本验证；控件不依靠压缩标签维持一行。窄宽度折行或切换行结构，三个档位的顺序固定。
- 检查浅色、深色、最低窗口尺寸、常规窗口、空池、多模型、长名称及展开编辑状态。

## 交互与真实性

- 多档位分配不改变模型全局启用开关；选中模型不触发请求或供应商激活。
- 档位开关支持键盘和 VoiceOver，明确呈现选择、禁用、保存和错误状态。
- 连接来自真实成员的档位集合；冷却、停用、凭据缺失、未测试都用文字解释。
- 不照搬概念图中的用户任务、虚构延迟、运行中状态或颜色对能力强弱的暗示。
- 接入、发现、排序、能力编辑和路由记录保持可达；高级设置离开主要模型浏览路径。

## 性能

- 沿用页面可见时的健康快照读取和原发现生命周期，不增加发现轮询。
- 模型池最多 200 个成员；目录最多 1000 个模型。用合成数据验证可见行渲染和滚动，避免整池一次挂载。
- 可视化采用原生 SwiftUI 与有界静态几何，无力导向物理模拟、常驻逐帧动画或循环装饰。
- 状态无变化不发布新的快照；几何只随布局与真实数据变化更新。
- 尊重减少动态效果；不以未经测量的帧率宣称性能。

## 验证

- UI 原生截图与控件、文本布局检查；必要的生产呈现逻辑回归。
- 网关专项回归与开发版构建；不安装或运行正式版，不调用真实推理服务，不读取真实凭据用于截图。
